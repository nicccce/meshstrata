## 完成行为

- 所有对象先克隆到本次编辑状态。取消/关闭/Escape/遮罩/离开路由对未保存修改提供丢弃或继续编辑；刷新有原生 dirty 提示。只读模式禁止编辑。显式保存才 upsert 被规则引用的新/修改目标；修改既有目标时生成新 ID，重置 TCP/UDP 验证，避免破坏旧策略引用。策略只 emit save(policy)，不 upsert policies、不改 published。
- Node Default 保存为仅 MATCH→新 node_default 目标的策略，兼容既定必须返回 EgressPolicy 的事件接口；owner 将它作为草稿引用处理。
- 规则支持增删、键盘可操作的上下移动，单 IP → /32 或 /128，CIDR 掩码规范化为网络地址，检查有序范围重叠并保留原顺序；唯一末尾 MATCH 固定，默认 REJECT。载入异常 MATCH 序列会提示并收敛到一个末尾 MATCH，保存前需用户审阅。
- `logic.ts` 提供 IPv4/IPv6 范围解析、BigInt 网络区间、重叠判定和目标校验。阻止已知同节点 Listener 的本机/本节点地址自指端口（含 IPv6 回环和 mapped IPv4 回环），保守阻止 lo、tun、utun、mihomo/clash/meta 接口。无真实网卡/透明代理探测，不能证明任意主机名或外部接口不会形成环。
- 代理认证只写 `sessionSecrets`；关闭、取消、卸载、切换策略、保存与 Demo reset 清理，不进入任何持久对象、事件参数、URL或预览。当前仅内存输入演示，不供离线检查执行认证。
- 目标 TCP/UDP 状态分开；HTTP、未经验证的接口/SOCKS5 明示业务 UDP REJECT，不回退默认出口。DNS 摘要显示已应用 node-wide upstream/revision/outbound/bootstrap，可跳转末端节点 DNS 页，缺省 outbound 为 Node Default、bootstrap 为 Not Checked；说明 DNS 与业务最终公网出口并非总一致。
- 共享策略显示引用线路及 draft/published 策略修订，默认另存新策略；选择准备更新全部引用时二次影响确认，返回同 ID 的下一修订，仍由 owner 统一验证和发布。
- `CheckEgressDrawer.vue`：选择 published/draft 修订、route/Target-only、订阅条目及出口目标；Target-only 显著说明绕过规则。缺失 ID、条目范围不符、缺失末端、策略末端不符均给出不可执行状态。历史策略修订不可用时阻止整线路检查，不擅用新修订。
- Destination / Egress IP / DNS Path / Client Coverage 独立结果；每次产生四个稳定 ID，未选项保存 Not Checked。目标连通性不宣称目标公网 IP；回显文档 IP 仅属于指定回显服务；DNS 结果说明覆盖范围；IPv6/UDP/WebRTC 无可观察能力保留 Not Supported，IPv6 目标不宣称成功。匹配 REJECT 或失效目标明确失败，无后续目标回退。
- 成功、Timeout、DNS、TLS、HTTP Access Denied 可明确选择演示，error/offline/partial/stale 场景有确定结果。结果使用 `workspace.checks`，保存 scope/route revision/policy ID/测试地址/时间/失效时间/规则解析 IP/命中规则/目标；支持搜索和状态筛选，缺测、空结果与 Stale 展示独立。修订不一致、目标变更/删除、策略更新或 TTL 到期会标记 Stale。
- 检查使用可取消有限 UI timer；关闭/路由离开/卸载/上下文变化取消，取消不生成结果或触发 completed。配对客户端只呈现模拟 Apply/Reconnect；重连先说明连接影响，绝不访问 localhost、修改连接或 DNS 缓存。
- 全部新界面文案放在本 feature 的英文 i18n，采用 Naive UI 和 scoped CSS。可搜索下拉、显式表单 label、键盘重排、窄屏单列和 44px 主要触控操作。

## 共享契约缺口与后续集成

1. `DraftData` 仅含 node/route/subscription/profile，route 也只有 RouteRevision，没有 EgressPolicy/目标表单字段。无法通过既定 `useDraft` 保存本抽屉的规则/目标编辑；没有借用 profile.text 或另建 localStorage。当前明确提示该限制，提供本次编辑、save 交 owner、cancel 丢弃和 dirty guard。集成应扩展非敏感 `DraftData.egress`（或 route 内 policy/targets 快照）及 `projectDraftData` 白名单，再接 `useDraft`；不要让同一 owner draft ID 出现多个 useDraft 实例。
2. 共享 Node/Route/Target 无已验证的 IPv6 业务能力字段，不能把 UDP/普通 verified 当 IPv6 证明。IPv6 parser 与规范化已实现；UI 禁止新启用 IPv6，已有 ipv6=true 可关闭，IPv6 规则可查看但禁止保存。需要增加明确的 enabled+verified end-to-end IPv6 能力才能开放。
3. EgressCheck 只有 route revision 和 policy ID，没有 policyRevision、targetRevision、DNSRevision / DNS 配置快照。当前借 route.policyRevision 与当前 policy 及 target.updatedAt 保守判旧；DNS-only 更新的结果失效仍需要公共契约扩展或 node owner 清理/过期相关 checks。没有伪装这些字段已支持。
4. 共享策略更新必须由 owner 一致更新所有引用并统一 review/publish；本抽屉只返回策略。新增目标可能在 owner 后续丢弃时成为无引用对象，由集成的引用回收处理。
5. 真实网卡清单、端到端 IPv6、任意透明代理环路与独立 UDP 能力仍为真实实现阶段验证；当前不调用网络或安装部署。

# P07 — Subscriptions and configuration delivery

Implemented only `web/src/features/subscriptions/` and this report. No staging, commits, branch changes, shared-file changes, network probes or business APIs.

## Delivered behavior

- Subscription list: URL-backed name/ID search, expiry/sync/route filters, sort and paging; missing filter references remain visible; remaining lifetime, rule links, usage/query timestamps; saved draft resume; empty/error scenarios.
- Four-step editor: name/description/future expiry, ordered published route selection, one rule profile, independently enabled All-Proxies and exit grouping, initial members, client preferences, review/diff/port allocation and cancellable local save. Typed `Draft.data.subscription` and `useDraft` provide explicit save, refresh restoration, discard and navigation guards. Editor instances reset on draft/object/demo reset. Rules round trip saves the original draft and passes sanitized returnTo/draftId; profileId on return updates the selection.
- Group identifiers use the shared exitGroupName helper. Same terminal/policy with different published revisions blocks output. Missing published paths, policies, targets, entries, duplicate/reserved names, stale initial selection, rule targets/provider references, multiple/missing MATCH and conflicting DNS mappings block generation.
- Each subscription × route owns an entry and isolated listener/port (all four protocols are conservatively isolated). Fixed-port conflicts block; automatic ports scan protocol/node/global pools, including pending reservations. Existing entry IDs/ports survive policy/group edits. Every save recomputes allocations against the current workspace.
- Detail Overview / Entries / Config / Usage; related nodes/routes/profiles/activity are linked. Extend expiry updates entries, link reset changes downloadVersion only, delete retains revoked subscription and entry records, offline revocation remains pending, explicit simulated sync confirms online identity/cleanup state. Ports remain reserved until cleanup confirmation and other resource references are checked. Releases/events are shared workspace records.
- Demo URL uses example.invalid and a non-sensitive version, separate from entry credentials. Full YAML and provider exports have distinct preview/download actions; provider contains proxies only. Full output includes DNS bootstrap and domain mappings, TUN/fake-IP defaults, IPv4 defaults, an early business UDP rejection and one final MATCH. Initial select members are emitted first. No management endpoint, reverse mapping, tunnel parameters or real credential is exported. Credential placeholders are explicit; copy failure exposes selectable text. Illustrative identities, when needed, live only in sessionSecrets and are cleared after the detail workflow.
- Existing CheckEgressDrawer is integrated at review and entry/config detail using its stable props/emits; no private P08 exports are imported.
- Usage is queried only by button, with finite cancellation and retained previous results on error. Per-entry cumulative bytes, connection counts, active snapshots and unavailable metrics have separate semantics. Totals exclude node/tunnel data and require complete matching metric/coverage with no reset. Partial scenario intentionally produces incomparable snapshots.

## Defaults and contract limitations

- Missing grouping/client values default to both groups enabled and TUN/IPv4/business UDP disabled. Missing downloadVersion defaults to 1. Missing autoPort uses automatic allocation; explicit false enforces the configured fixed port. Pool precedence: protocol pool → node pool → global pool.
- Domain has no verified per-client IPv6 or per-segment business UDP/DNS coverage record. Those preferences can be selected for review, but validation blocks generation and explains the missing evidence. No claim of firewall/kill-switch protection is made.
- Workspace stores only the latest policy revision. A route pinned to an older unavailable policy revision blocks output rather than silently adopting the new revision. A future shared revision-history contract would permit valid old revisions.
- Exported YAML is an offline demonstration with redacted placeholders, not a deployable/verified Mihomo artifact. Real protocol credential shaping and version-specific runtime acceptance remain backend/integration work.

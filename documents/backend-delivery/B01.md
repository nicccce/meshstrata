## 登录与初始化行为

`auth.Options` 精确字段：`Clock func() time.Time`（默认 `time.Now`）、`Random io.Reader`（默认 `crypto/rand.Reader`）、`Bootstrap *auth.Bootstrap`、`AllowedOrigins []string`（必填 HTTPS origin 精确白名单）、`CookieName string`（默认 I00 OpenAPI 契约名 `meshstrata_session`；额外只接受合法 `__Host-` 名称）、`SessionTTL time.Duration`（默认12小时，范围5分钟至24小时）、`AttemptWindow time.Duration`（默认1分钟，范围10秒至1小时）、`MaxAttempts int64`（默认5，范围1至20）。不读取全局环境、不注册全局路由；时钟/随机源均可注入。

`auth.Bootstrap` 有 `SHA256 []byte` 与 `ExpiresAt time.Time`。SHA256 必须是 **32随机字节、规范无填充 base64url 编码的43字符 proof 本身**的 SHA-256；不是原始随机字节的 hash，也不是人类口令。仅接受调用方从可信本地资料提供的 digest/到期时间；Options 不提供从请求选取可信源的通道。nil 明确禁用初始化，即使管理员表为空也返回403。proof 必须以 `X-Meshstrata-Bootstrap` 请求头提交，同时验证 Origin，计算密码后再次检查过期。持久 singleton initialized 墓碑 CAS 消耗与管理员插入在同一 Write；密码计算在事务外。重复初始化409，竞争仅一个创建成功；回滚会连同消耗标记一起撤销。已初始化状态即使管理员行丢失也不会重新开放，恢复须走未来受控本地运维流程。

| 方法与路径 | 输入与保护 | 成功结果 |
| --- | --- | --- |
| POST `/api/v1/auth/initialize` | JSON `{username,password}`，可信 bootstrap header，必需正确 Origin；独立限速；此时没有 session CSRF | 204，不自动登录 |
| POST `/api/v1/auth/login` | JSON `{username,password}`，必需正确 Origin；独立限速；无需既有 CSRF | 204，Set-Cookie 新 opaque token |
| GET `/api/v1/auth/session` | 有效 cookie；不要求 Origin/CSRF，但显式错误 Origin 或 `Sec-Fetch-Site: cross-site` 拒绝 | 200 `{username,expires_at,csrf_token}`，时间为 UTC RFC3339；不回传 session token |
| POST `/api/v1/auth/logout` | cookie + 必需正确 Origin + `X-CSRF-Token` | 204，服务端删除当前会话，过期清除 cookie |
| POST `/api/v1/auth/password` | 同 Write 保护，JSON `{current_password,new_password}`，独立限速，校验当前密码 | 204，CAS 更新密码/修订，原子删除全部 session，清除 cookie |

用户名限1至64字符 `[A-Za-z0-9_.-]`；新密码限12至1024字节，不 trim、不截断。JSON 请求限4096字节，要求 application/json，拒绝未知字段/尾随对象。会话令牌为32随机字节的规范 base64url，数据库只存 SHA-256、管理员修订、创建/到期时间。每次登录发新令牌并原子删除请求中旧会话，避免固定会话；未带旧 cookie 的独立登录可并存。改密码在事务内重新验证会话及密码修订；已退出的旧会话不能在竞争中修改密码。到期边界为 `expires_at > now`，无滑动续期；登录时清理过期记录。

Cookie 永远 Secure/HttpOnly/SameSite=Strict、Path=/、无 Domain，不支持明文 HTTP 降级。CSRF 为以当前 opaque token 为 HMAC-SHA256 key、固定用途标签为消息派生的独立值，只在受保护 session 响应中交付，不把明文 token/CSRF 存入数据库。Write 要求 session、精确单值 Origin、精确单值 CSRF header；重复 cookie/Origin/CSRF、缺失/错误值均拒绝，不调用业务 handler。Read 仅用于管理读方法；I01/B02 必须给所有写操作和敏感 POST（包括取下载链接）使用 Write。没有 CORS 放行或重定向登录。

三个固定服务端限速桶 `initialize/login/password` 持久化于同一 SQLite；每桶默认每分钟最多5次，成功、错误口令及格式错误均消耗尝试，错误 Origin 在限速前拒绝。没有用户名/IP/代理头基数，不依赖 Redis，重启不清空限速。单 Service 同时只允许一个 KDF；繁忙时立即429，不排无界队列。全局单管理员限速可能导致攻击期间管理员也需等待窗口，这是当前明确取舍。

所有认证/Guard 响应带 no-store/no-referrer/nosniff。错误采用 domain 外层：400 `INVALID_ARGUMENT`、401 `UNAUTHENTICATED`、403 `FORBIDDEN`、409 `REVISION_CONFLICT`、429 `RATE_LIMITED`（含 Retry-After）、500 `INTERNAL_ERROR`。错误用户名与错误密码同401且不反射输入；数据库/密码库错误只返回通用500，不输出内部细节。没有请求体/密钥/令牌日志。

密码使用 `golang.org/x/crypto/argon2.IDKey`，不是自制算法；PHC 严格版本 `$argon2id$v=19$m=65536,t=3,p=4$...`，盐16字节、tag32字节。参数采用 [RFC 9106 §7.4 第二推荐](https://www.rfc-editor.org/rfc/rfc9106.html#section-7.4) 的64MiB/3轮/4 lanes，适用小内存场景；同时限制 KDF 并发1。64MiB 是单次算法工作内存，不是整个 Go 进程 RSS 保证，校验及新 hash 连续执行还受 GC/其他模块影响。已核对 [Go 官方 v0.48.0 源/版本](https://go.googlesource.com/crypto/+/refs/tags/v0.48.0/) 和实际下载的 argon2 源文档；该 tag 要求 Go1.24，基线 Go1.27.3 满足。没有声称这是最新版本；不从数据库读取可任意放大的 KDF 参数。未来参数升级须扩展严格 parser/迁移策略。

## 加密、密钥与凭据轮换

`secrets.Options` 精确字段：`CurrentKeyID string`、`Keys map[string][]byte`、`KeyFiles map[string]string`、`Random io.Reader`。KeyID 限1至128字符 `[A-Za-z0-9_.-]`；每个版本只能从 Keys/KeyFiles 二选一提供，AES key 必须32字节。生产建议 KeyFiles；Keys 供可信内存注入，构造时复制，不留调用方 slice 引用。当前版本必须存在，历史版本一并加载；构造完成后的 keyring 不变，轮换通过新 Cipher 实例及 Credentials.Rotate 显式执行。

使用标准库 AES-256-GCM（[Go 官方 cipher 文档](https://pkg.go.dev/crypto/cipher#NewGCM)）：每次随机96-bit nonce、128-bit tag，信封 magic `MS` + 格式版本1 + 算法1 + nonce + ciphertext/tag。AAD 以长度前缀认证 credential ID、purpose、KeyID 与格式/算法。每个 plaintext 限1MiB。不同 ID/用途/KeyID、损坏信封、未知历史版本都返回 nil 明文与 `errors.Is(secretstore.ErrDecrypt)`；无效绑定为 ErrInvalidBinding，缺当前密钥/随机失败为 ErrKeyUnavailable。不从 Open 失败推导创建、替换或修复密钥。

绑定 purpose 允许小写字母/下划线的未来扩展；仓储仍受已安装002 purpose CHECK 限制，只能持久 `proxy_entry/internal_proxy/dns_api/location_api/management_ca/tunnel/certificate`。测试确认 `subscription_download` 当前不能入库，B08/010 再扩展，本轮不修改002。节点私钥及本地 Mihomo secret 不得经此服务；B02 的 CA 私钥密文可由 purpose owner 使用，但不生成或外发 CA。

KeyFiles 只读取预先准备的绝对规范路径，不接受文件/目录 symlink。最近父目录须0700、文件须0600、两者须归有效服务 UID；文件须普通文件且精确32字节。祖先不可被其他用户写，sticky 临时目录允许；OpenRoot 限定最终打开范围，打开后 SameFile/权限/owner/长度复查。缺失、权限错误、截断、重复来源一律脱敏失败，不生成文件。此实现依赖 Linux/Unix 文件权限，不依赖 systemctl 或 glibc；测试在 Linux amd64 执行，Alpine/OpenRC 正式运行留 T01/B17 验收。

备份必须同时保存：一致 SQLite 快照（含 ciphertext/KeyID/绑定/撤销）与分离保管的完整历史本地 keyring；不要只复制活动 WAL 主文件。主密钥不得进入数据库、API、日志、普通导出或仓库；安装器/备份实现留 B17，B01 没有新建备份路由。重启前不要删除仍被历史密文引用的 key。先配置新 current + 保留旧 key，逐记录 Rotate，确认所有活跃引用已转移，并安排旧备份恢复边界后再退役旧 key。随机 GCM 每 key 加密次数必须低于2^32，当前没有持久使用计数/自动全库轮换调度；这是运维轮换预算，不应被当作无限 nonce 空间。

凭据 Create 先加密，再短事务插入；Open 先按 ID+purpose 查未撤销行，再解密。Revoke 是显式、幂等墓碑操作，不删密文、不恢复旧行。Rotate 在事务外加载/解密/按相同 binding 重新加密，再短事务 CAS 比较旧 key_id+完整旧 ciphertext，且要求 revoked_at IS NULL；并发轮换/撤销使 CAS 返回 ErrConflict，不复活记录。003 触发器也禁止已撤销凭据清空撤销或更改密文/key_id。未找到/已撤销为 ErrUnavailable，在调用 Cipher 前拒绝。凭据服务错误保留 errors.Is；未来 HTTP owner 必须映射/脱敏内部数据库错误，不能直接输出 err.Error() 或 sqlc credential DTO。

`Credentials.Open` 的明文由调用方所有，调用后 clear；轮换内部 defer clear，构造临时 key buffer 会清理。Go 字符串、AES 扩展 key、编译器复制、Argon2 工作区及 GC 无法保证完全清除；没有声称提供安全内存或全进程擦除。主密钥全生命周期留进程本地，退出/备份隔离与操作系统权限仍是边界。普通 DTO 只有 credential 引用；任何明文下发/导出必须经对应 owner 的显式授权私有流程。Credentials 方法自带短事务，不可从 Database 回调内调用；未来 B08/B13 需要将 credential 引用与业务行原子更新时，应先用 Cipher 在事务外准备信封，再由 owner repository 在同一 Write 调用生成查询完成业务 CAS/插入/撤销，不能把独立 Create 与另一个事务误认为一次原子操作。

## 直接可用的接口与构造约定

`internal/secretstore.Cipher`包含`Seal(ctx, Binding, plaintext) (Sealed,error)`、`Open(ctx, Binding, Sealed) ([]byte,error)`。Binding为credential ID + purpose；Sealed的KeyID映射002的key_id，Ciphertext映射ciphertext，信封包含算法/格式版本。B01必须认证两项binding，密钥ID仅表示密钥版本。保持002的purpose集合；B08/010再增`subscription_download`和`subscriptions.download_token_credential_ref`，不可提前改002。密文可由仓储持久及一致备份；不经HTTP/节点通道。主密钥只留本地；明文在进程内按需使用，仅可经对应owner明确授权的私有下发/导出流程离开（例如B08获取能力链接动作），不能进入普通DTO/日志。CA私钥只在Controller，节点私钥/本地Mihomo secret不经过该接口。调用方负责清理明文缓冲；B01文档说明Go内存清除局限。B02的CA属于B02，B01不生成/管理证书。

失败语义固定：Seal没有当前密钥返回`ErrKeyUnavailable`；Open未知历史密钥、损坏信封或绑定不符均返回nil明文及可`errors.Is(ErrDecrypt)`判断的脱敏错误，不自动建新密钥覆盖。无效binding返回`ErrInvalidBinding`。repository未找到/已撤销凭据在解密前拒绝，不能从密文形状猜用途。轮换在事务外解密并按相同binding重加密，短事务内CAS旧key_id/密文；并发撤销不得复活。时间/revoked_at由repository管理，不放Cipher中。

`storage.Database`由现有`*storage.Store`实现：`Read(ctx, func(*dbgen.Queries) error)`与`Write(...)`。B01/B02各自包内`NewRepository(db storage.Database)`仅保存此接口。HTTP handler只接收模块service/repository的窄方法，不接触Database/dbgen；repository不另开连接、不依赖Store私有db。Read是只读调用约定（SQLite驱动不保证通过ReadOnly选项禁止SQL写入），不是安全沙箱；I01审查询确保Read无写操作。Read/Write均在同一Controller池创建短事务；回调不可保留Queries、起goroutine、嵌套或再调用Store，否则单连接可死锁。所有参与同一不变量的生成查询放同一个Write。加密、签证、网络在外部完成，再在短事务内重查有效期/版本/CAS；一次性token消耗、节点证书记录与安全重试响应关联原子提交，先提交再回复。

I01使用以下**固定构造约定**接线；B01/B02需实现这些签名及自己的Options类型（本轮不实现业务包）：

```go
// controller/internal/auth: clock、随机源、可信bootstrap策略、cookie/Origin策略
// 在本模块Options中显式注入，测试不依赖真实时钟/全局环境。
auth.New(repo *auth.Repository, options auth.Options) (*auth.Service, error)
// *auth.Service实现adminauth.Guard，并提供Handler() http.Handler。
// Handler只处理/api/v1/auth/*，初始化/登录单独限流、校验Origin/bootstrap。
secrets.New(options secrets.Options) (secretstore.Cipher, error)
// Options显式提供本地key来源/当前key版本；不让Cipher自行打开数据库。
enrollment.New(repo *enrollment.Repository, cipher secretstore.Cipher,
    guard adminauth.Guard, options enrollment.Options) (*enrollment.Service, error)
// 提供ManagementHandler() http.Handler、EnrollmentHandler() http.Handler。
// ManagementHandler内部按方法应用guard.Read/Write，不能只保护页面路由。
```

I01顺序：单次`storage.Open` → B01/B02 `NewRepository(store)` → B01 Cipher/auth → B02 enrollment（注入Guard/Cipher）→ 将auth Handler与B02 ManagementHandler注册8443。构造失败（nil依赖、无效Options、缺密钥/CA不可恢复）返回脱敏error、停止启动，不暴露半套业务路由。管理handler未鉴权/CSRF失败返回domain错误401/403且不进入业务；无资源404、过期/已消费token为稳定非敏感错误，CAS/幂等冲突409。基础数据错误保留`errors.Is`，HTTP层统一映射并隐藏sqlc/加密/签证详情。

9443由B02独立构造TLS listener与路由：EnrollmentHandler只在服务端TLS认证入口接受一次性body token+CSR，先校验Controller信任再发送token；control管理通道在TLS配置/握手或路由边界强制节点mTLS，绑定证书node_id及未移除状态。入网端点与mTLS可共用9443监听但必须分别强制策略，不因首次入网无客户端证书而放松control。不装Guard、不用cookie作身份，不让Agent导入`controller/internal`；Agent仅依赖根`internal/{pki,control,...}`及自己的包。B02控制包提供独立Options/New构造及关闭生命周期，Handler、TLS配置、证书续期/撤销回调、ArtifactSource接线均写入B02报告，由I01审后接入；本轮不冻结后续调度细节。

B02用fake Cipher/Guard做单测，不导入B01具体包。B01/B02不依赖彼此新增表，凭据仍用002；模块专用认证/入网repository查询各自在自己的SQL提案中给齐，B02不要调用自行打开数据库的“测试helper”作为生产接线。所有持久字段通过sqlc，HTTP层不写任意SQL。

## B03 → B05 的最低适配边界

B03独立锁定内核及Linux客户端版本/摘要/架构，报告其Options/New及实现接口：输入为平台实例路径/私有工作目录、受限配置文件路径和预期Listener（node/Listener ID、协议、地址端口、配置摘要），本地secret只在Agent内存/受限本地文件。配置校验返回稳定字段错误；重载返回应用尝试结果，实际Listener/认证/撤销探测另返回带时间和摘要的证据（成功/失败/未验证），不把HTTP200当Verified。B05之后负责候选、checkpoint、原子切换、到期、rollback/outbox；B03不实现runtime、Controller调度或注册业务路由。此轮不预定未来配置包格式，四协议实际字段与B05输入按B03报告由I01复核。

最低测试：B01登录/退出/暴力限制/bootstrap抢占、cookie/Origin/CSRF、密文错purpose/错ID/损坏/缺key与轮换不复活撤销；B02假CA/错域名、到期/重放/并发一次消耗、提交后重试、移除断旧通道/错误身份、事务失败不半入网；B03固定版本四协议转发/重载假成功/独立撤销与存量连接/缺配置/私有目录/无通用入站。真实网络/多机仍留T01；无法在本机完成的项如实标阻塞，mock不冒充实测。

## 同目录并行的独立验证

业务会话可在忽略目录 `.local/backend-check/Bxx/run-*` 创建**基于派发时I00提交**的临时副本。命令：

```bash
python3 scripts/backend_check.py B01 --base <主协调填入的I00完整提交hash>
python3 scripts/backend_check.py B02 --base <同一I00提交hash>
python3 scripts/backend_check.py B03 --base <同一I00提交hash>
```

每个会话只运行自己的命令。脚本以`git archive`读取提交，按上述白名单覆盖本模块源码（含删除）/SQL提案，不读取其他会话当前编辑、node_modules、.local、真实密钥或业务数据库。独占目录只允许源码/脱敏静态fixture，不存真实密钥/数据库/二进制；有实际secret的JSON/YAML也禁止放入源码目录。新建的未跟踪源码也会覆盖；非源码/符号链接拒绝。共享接口变更只能向I01提案，不能通过拷入副本偷改接口。每次生成新副本，`VALIDATION.json`记录基线、覆盖文件及精确依赖；该文件不含token或真实配置。

迁移提案在副本装入003/004/005，前序其他模块槽位用**临时占位SELECT 1**，不读取兄弟提案、不给共享dbgen写权限。若依赖其他模块新表/字段导致失败，说明接口越界或确有集成依赖，交I01处理；不得复制兄弟代码来制造通过。依赖提案`Bxx.deps`每行精确`module@vX.Y.Z`（可带精确预发布或pseudo-version），无依赖可缺省；仅在副本`go mod edit`/`tidy`，正式go.mod/go.sum由I01锁定。sqlc、模块单测/vet及公共storage/api测试在副本运行；不装前端、不全量构建、不复制缓存，Go使用仓库已配置.local/cache，构建固定-p1/GOMAXPROCS=1，脚本flock串行保护整个检查。原工作区也不得绕过锁另跑大构建。

`--prepare-only`只准备副本，不能当检查通过；默认检查在缺少任一约定模块源码时明确失败，不用仅storage/api通过冒充模块交付。需要额外针对性命令时使用相同 `.local/cache/backend-check.lock` 的flock和固定低并发，明确副本绝对路径；不在副本运行Git命令。报告写清运行位置、基线、提案依赖与真实退出码，不把临时副本成功称为原工作区/集成成功。

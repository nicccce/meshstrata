# T02 阶段二独立双平台验收计划

T02 使用 I02 最终推送提交的普通 Controller 和 Agent。旧 `f570207` 产物用于 T01 历史证据，T02 重新构建并记录完整提交、版本、SHA256SUMS。I02 本机证据见 [集成报告](I02.md)。实际 T02 会话由主协调派发时登记。

## 固定产物和隔离准备

在构建机准备已按锁校验的未压缩 Mihomo。生产与测试 helper 分目录、分 SHA 清单。服务器运行预编译 Linux amd64 程序，Go、Node 和前端构建只在构建机运行。

```bash
scripts/integration/build-stage2.sh "$PINNED_MIHOMO"
artifact_dir=".local/stage2-artifacts/$(git rev-parse HEAD)"
(cd "$artifact_dir" && sha256sum -c SHA256SUMS)
(cd "$artifact_dir/test" && sha256sum -c SHA256SUMS)
python3 scripts/integration/stage2.py \
  --bin-dir "$artifact_dir" --mihomo "$artifact_dir/mihomo" \
  --inspect "$artifact_dir/test/stage2-inspect" --peer "$artifact_dir/test/stage2-peer"
python3 scripts/integration/stage2.py --suite materials \
  --bin-dir "$artifact_dir" --mihomo "$artifact_dir/mihomo" \
  --inspect "$artifact_dir/test/stage2-inspect" --peer "$artifact_dir/test/stage2-peer"
```

主协调提供授权测试机，地址与凭据从 `.local/test-servers.md` 读取，报告只用 Ubuntu、Alpine 标签。先以 SSH 核对主机身份、当前监听、可用 RAM、`uname -m`、`/proc`、磁盘与时钟，再验证本轮独占 HTTPS、mTLS 和业务 TCP/UDP 所需公网连通。有明确本地服务阳性与跨机失败时保留两端证据，暂停依赖该公网窗口的项目并汇报。早期开放记录无效于本轮预检；计划不变更云规则或既有防火墙。

每拓扑在两机创建新 0700 根，例如 `/tmp/meshstrata-t02-<run>`。复制固定产物到 `artifacts/`，复制 [stage2-host.sh](../../scripts/integration/stage2-host.sh)，在每台校验完整产物和 test 清单。配置文件 0600，绝对路径置于本轮根下；同机 both 使用各自 Controller/Agent state 和管理 socket。Alpine 串行初始化/入网/任务重探，留资源监测余量。

```sh
umask 077
test_root=/tmp/meshstrata-t02-example
mkdir -m 700 "$test_root"
# 通过授权 SSH/SCP 放置 artifacts/、stage2-host.sh 和本轮 JSON 配置。
sh "$test_root/stage2-host.sh" "$test_root" verify
sh "$test_root/stage2-host.sh" "$test_root" controller prepare-local
# 在可监督的 SSH 会话前台运行以下服务。
sh "$test_root/stage2-host.sh" "$test_root" controller
# Controller ready 后，经 stdin JSON 初始化，使用新短期 bootstrap proof。
sh "$test_root/stage2-host.sh" "$test_root" controller initialize-admin < "$test_root/admin-private.json"
```

Controller JSON 按 `scripts/integration/stage2.py` 的 Lab 配置准备；`secure.allowed_origins` 必须与管理 HTTPS 的实际 URL 一致，`controller_url` 则是两个 Agent 都可达的 mTLS URL。为两个目标从管理员 API 新建 enrollment，走真实管理员 cookie、Origin 与 CSRF。每节点保存该次发出的 CA、指纹和入网 token 到私有根，在该节点生成管理私钥。使用新身份和证书期限，核对 mTLS 错误与证书过期分别取证。

Agent JSON 需要独立 `state_dir`、`control.mode=runtime`、`controller_url`、`ca_file`、`ca_fingerprint`、`node_id`、入网期间的 `token_file`，以及 `runtime.mihomo_binary` 指向本轮 `artifacts/mihomo`。按下列命令操作。结束入网后移除 token 文件。按协议将本轮 TLS/REALITY 文件放入本节点私有 `runtime/config/materials`，文件名为注册的 `<id>.<purpose>`；`runtime.materials` 列出被允许的 ID/purpose。运行时从不给远端选路径。

```sh
sh "$test_root/stage2-host.sh" "$test_root" agent enroll
sh "$test_root/stage2-host.sh" "$test_root" agent prepare-runtime
sh "$test_root/stage2-host.sh" "$test_root" agent
```

按 [本机驱动](../../scripts/integration/stage2.py) 的 `Lab.submit` 和 `Agent.target` 生成严格 JSON。根字段 `mutation` 和 `plan`，Plan 使用 `kind,subject,deadline,nodes`，节点使用 `node_id,expected_revision,template,depends_on`。节点 revision 从真实管理 API 读取；给模板设置下一修订和当前 epoch，组件 pin 用精确 typed JSON 的 SHA-256。授权使用新 identity 及真实到期 UTC，凭据按协议生成。保持 Listener/tombstone/资源要求的排序。提交前优雅停止 Controller 并确认状态锁已释放，然后取回 stdout 的 task ID 并恢复监听。动作回滚、取消和重试走管理 API 和任务账本 revision。

```sh
sh "$test_root/stage2-host.sh" "$test_root" controller submit-release < "$test_root/release-private.json"
sh "$test_root/stage2-host.sh" "$test_root" controller
```

## 两拓扑逐项门槛

| 项目 | 操作与所需证据 |
| --- | --- |
| 两次拓扑 | Ubuntu Controller + Ubuntu/Alpine Agents，随后 Alpine Controller + Alpine/Ubuntu Agents。每次新证书和数据库，保持宿主既有 Mihomo。记录核版本、pidfd 支持、监听、证书、内存峰值/OOM。 |
| 普通生产路径 | 真实提交、密文落库、授权下载、两节点 DAG。以下游离线/未验证/监听失败作为负向控制。抓真实 begin、目标证据、Controller 入库、依赖入口发出与最终 task DTO，标出时间和摘要。分别证明各节点 TCP 与业务 UDP 正向回显、新错凭据拒绝。对四协议逐方向复验；VLESS 使用受控的 P-256 TLS 目标。 |
| 传输/鉴权 | 错 CA、错节点证书、错目标 revision/digest 时无数据或无 receipt；失首个 artifact 响应但 Open 已提交时，原任务可重投相同 artifact。终态换 task 时核对 `GRANT_ORIGIN_UNCERTAIN`，显式 cleanup 中已证实子集独立回执，未知保留端口，独立新授权端点可恢复业务。 |
| 控制与进程故障 | Controller 提交后未发送、已下载未入库、提交结果未回执处崩溃。Agent 在 Candidate、Applied 未验证、Verified/outbox 未确认处强制终止。核对节点 CAS、目标 revision、原 task ID 和真实已落盘阶段。恢复依据 fresh probe，重复结果只回执，同 seq 异 payload 拒绝。正常 Agent 退出检查同 PID/存量连接；保护性故障只停止受管实例。 |
| 时钟与到期 | 断 Controller 后让授权到期，逐次检查旧连接关闭、新旧凭据、另一身份同一存量连接及真实 endpoint 占用；再以 Agent 与内核均停机跨 TTL，离线先启动 Agent 并检查旧快照过滤，最后恢复 Controller。记录时钟和 high-water、墓碑和原 task restriction，不用调 SQL 模拟到期。 |
| 端口、回退和移除 | IPv4/IPv6 固定地址、wildcard/双栈、TCP/UDP、真实 foreign holder、API 接受但未监听、回退本身失败、迟到结果和删除竞态。未确认/仍引用均不可重新分配，确认零引用后真实重用。回滚新 artifact/revision，旧身份不复活。删除使原证书/WS/下载失效，父任务仍 pending，已有关系的实时授权 peer 在真实条件下独立清理。 |
| 账本与分页 | 观察含终态 grant 的 restriction、receipt 丢失重投、跨序不倒退。100 条计数分页和实际 1 MiB 帧限制分别记录每页条数、bytes、每序号确认前后 outbox。生产多页积压安排足量已合法生成授权/结果，并保持输入会话隔离；模块已验证的 fixture 分页与生产网络证据分开。 |
| 平台与失败证据 | 设备或文件系统故障注入与软件 SIGKILL 分开。T02 可在监督的前台独立进程上完成取证；Ubuntu systemd cgroup 与 Alpine OpenRC 正式安装/生命周期交付留 T07。保留首次失败、重试命令及准确未执行项。 |

每一步分别记录 Controller task 的 `target_digest`、`b04_node_state.artifact_digest` 及 `effective_digest`，以只读方式收集 Controller 账本和阶段信息。Agent 离线时用 `test/stage2-inspect -state <Agent state_dir> -node <id>` 收集五阶段摘要、epoch、outbox 数和墓碑数。远端只需执行预编译 helper；若远端缺 sqlite 工具，可在受信构建机对停止后的数据库备份做只读核对。证书私钥、凭据、完整包/控制异常帧均留私有证据目录。

清理先正常退出本轮 Agent 和 Controller，再执行 [stage2-host.sh](../../scripts/integration/stage2-host.sh) 的 `stop-kernel` 和 `audit`。若此前 SIGKILL 导致僵置 socket，只移除本轮确认无监听的 socket，复查公网端口回收和原宿主进程/监听一致。真实程序 PID、测试 helper PID、SSH 复用连接和临时回显分别核对。报告说明未验或受阻项，等待主协调审核后再推进。

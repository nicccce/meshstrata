`subscriptions.NewService(stage3.SubscriptionsOptions) (*subscriptions.Service, error)` 实现完整 `stage3.Subscriptions`。单管理员作用域按操作和 IdempotencyKey 保存含 CAS 条件的请求摘要与原始安全结果。`Create/UpdateConfig/Renew` 原子写入审阅 Pin、固定 Profile/Route Pin、顺序和入口意向；响应是已持久化的状态，发布尚未完成时是 Pending。纯规则、分组、顺序和名称变更保留已确认且仍获授权的入口；线路 Pin 更换或续期分配新身份、凭据和租约，保留旧代墓碑。软到期仍可显式续期，删除的订阅不可续期。一个配置最多 128 条且线路唯一。创建省略模式时采用 TUN 和两个分组开启；显式给出模式时两个布尔值按输入处理。IPv4、拒绝业务 UDP，DNS 必须配置三组明确上游（无默认、无隐式直连），fake-IP 与规则/DNS 渲染由固定的 B07 ClientBuilder 实现；B08 不接受缺能力证据的 IPv6/业务 UDP 偏好。

010 新增 `b08_revisions`、`b08_heads`、`b08_revision_entries`、`b08_intents`、`b08_requests` 和持久时钟下限 `b08_clock`，并保留 002 的订阅、稳定条目、认证代次、凭据、Listener FK 及 Listener 引用。入口凭据严格按 `stage3.ProxySecret` 私有 JSON，通过 B01 `ProxyEntry` 加密入 002。Reconcile 先持久标记开始分配，再用同 OperationID 调 `ReserveIngress`；核对真实 Listener 的节点、端口、协议、凭据归属后存租约，随后重新检查当前修订、到期和撤销，在短事务提交 002 条目、身份、引用与 010 代次关系。只有提交成功才调用 `ApplyEntry`。任务回执必须匹配 TaskID、完整 Subject Pin、OperationID，且状态为 published、授权仍有效；确认某代时还验证它是 002 最新未撤销身份。审阅版中的所有入口确认后才推进下载头。旧快照只在所有旧条目仍有效时保留；未提交或失败的新入口不会交给生成器。

`subscription_download_credentials` 是用途固定的单独 envelope 表。010 给 002订阅增 nullable FK，约束归属、用途、token 版本和 hash；保留既有 credentials CHECK、CA FK 及旧 hash。32 个随机字节的 raw base64url token 独立于入口认证；库只保存 SHA256 验证值和绑定订阅 ID、ref、版本的 B01 `SubscriptionDownload` 密文。重置/删除在 CAS 事务中撤销旧 envelope 并更换/清空指针，重置不影响入口。旧库 hash-only 不猜 token，显式重置后可恢复链接；没有审阅的 010 入口快照时仍拒绝生成。每次完整配置/provider 下载在生成前后检查 token hash/版本、订阅 CAS、确认快照、当前未撤销身份和有效期；解密与生成在事务外。仅投影本订阅入口密文，audience 为订阅 ID；失败统一 NOT_FOUND（取消保留 context 错误）。清除可清除的短期明文字节和放弃的生成产物；Go 字符串由冻结接口指定，没有跨请求明文缓存。

## I03 接线

- 组合根传入同一 `storage.Database`、B01 Cipher/Guard、B06 EntryRoutes、B07 Profile/ClientBuilder、B04 ReleaseState 和固定 HTTPS PublicOrigin。安装 010 后统一 sqlc；检查 B07 规则方案版本双写/持有 002 `rule_profile_revisions(profile_id,revision)` 父记录，B06 已发布路线有真实 002 `routes.id`。路线删除/归档网关须用生成查询 `B08RoutePinInUse` 检查精确 ID/revision/digest 的活跃或清理未确认引用，保留固定版本。
- Worker 在每轮按 `(*Service).PendingIntents(context.Context, domain.ID, int) ([]domain.ID, error)` 的 ID 游标分页，到尾部重新从空游标扫描。调用 `Reconcile(ctx, intentID)`（不是 taskID/cleanupID）；单条出错继续其他条目，退避后再扫，不能吞掉过程取消。每个授权外部调用在数据库事务外，入网关时另开自己的共享库事务。
- I03 的 ReserveIngress 先以 OperationID/精确请求摘要重放旧租约；新建前在自己的同一事务调用 `subscriptions.CheckReservation(ctx, q, stage3.EntryReservation, now) error`，跨账本网关负责独占真实端口和 Listener，不信任 B08 的准备状态等同已分配。I03 的 SubmitV2 先以 OperationID/精确摘要重放持久 task；新提交及武装前在各自事务调用 `subscriptions.CheckDispatch(ctx, q, operationID, kind, subject, now) (stage3.EntryChange, error)`，将返回的身份、代次、期限、节点 epoch、租约与实际 grant/tombstone/Origin、节点配置和任务核对；只凭预检不能跨事务武装。Deadline 控制新建/武装，已接收的任务可精确重放，从而恢复丢失的响应。把实际 Subject/OperationID 原样带回 ReleaseState。
- 续期、删除、到期和失败候选都持久撤销旧代；清理按单独的稳定 Cleanup OperationID，使用真实旧身份、旧 Listener 和原审阅 Subject。发布状态与节点清理确认分开，只有 Cleanup 的精确 published 回执及入口节点 Cleanup=confirmed 才撤销 B08 的 Listener 引用和入口 credential；网关在自身 ledger 真实确认后按其统一端口 sweep 回收。离线或不确定时保持 Pending。Reserve 已开始但没有可提交的旧 grant 时，I03 需按原 OperationID 对账自己的 reservation/旧任务/Origin，原子阻断迟到武装并处理 lease；有“从未武装”证据才可在同一事务调用 `subscriptions.ConfirmUnarmed(ctx, q, operationID, listenerID, observedAt) error`，回收端口使用 B04 自有账本。仅凭 B08 没写到 Listener、deadline、错误或重启都不构成证据。已尝试清理却在远端永久终止的任务保留 Pending；冻结接口没有清理任务补派/terminal 授权换 OperationID 的入口。I03 若需要跨终态重派，需用真实 task + identity + Origin 证据设计持久重派与回执据点，不能在每轮随机重写 ID。
- 管理 handler 通过 Guard 作用域调用服务，普通响应使用 `subscriptions.ProjectManagement(stage3.SubscriptionView) subscriptions.ManagementView` 显式投影和适配冻结 wire，不能序列化 PublishedRoute、GenerationInput 或密文引用。Copy URL 仅注册 Guard.Write 内的 POST `/api/v1/subscriptions/{subscription_id}/download-link`。可接模块 `(*Service).HTTPHandler() http.Handler`：从受信 HTTPS server 的外层分派，先调用 `subscriptions.SensitiveTemplate(*http.Request) (string,bool)` 再进入任何 ServeMux、标准化路径、HTTP→HTTPS 重定向、access log/trace/metrics 中间件；敏感请求原样交此 handler，只记录模板，反向代理同样屏蔽 URL/query 和请求、响应体。标准 GET `/subscriptions/v1/config/{token}` 是完整配置，不需 header；本模块未开放可选 bearer 兼容、query token 或 provider 路由。provider 走单独的 `DownloadProvider` 私有调用。测试通过 Handler/Recorder 调用真实 B01 Guard，没有启动网络监听。
- 002 对 `(subscription_id,route_id)` 是永久唯一且保留墓碑：已 materialize 并删除的同线路不能在同一订阅内换新 entry ID，当前返回 DEPENDENCY_IN_USE；若产品要允许删除后重新加入同一线路，I03 需审查可历史化的条目关系迁移、保持所有 identity/B04 FK，不能复活旧 entry。保留同一未确认 Pin 的 config-only 编辑同样先拒绝并等当前发布；避免改写已派发的审阅 Subject。旧 002 记录无固定 Pin 或租约历史，未自动领养或伪造下载快照；Reset、Get 与本地 Delete 授权撤销可用，旧授权的远端清理由 I03 的旧 002/B04 账本处理。Create 的自选初始组选项若要在 Review 前引用 entry ID，冻结契约缺少分配后预览的 draft ID 回路；I03 应设计非秘密草稿预览或等创建后按安全 ID 编辑，勿把 route ID 当 entry ID。

## 实现与安全边界

- `internal/pki`：Ed25519 管理 CA、PKCS#8 私钥、CSR、自签 CA 与公钥匹配检查、证书签发、CA SHA256 指纹、TLS 信任配置。节点证书只有 clientAuth/digitalSignature，以唯一 URI SAN `meshstrata://node/<node_id>` 绑定身份；不从 CN、请求 JSON 或来源 IP 推导节点。Controller 叶子证书只有 serverAuth，SAN 必须覆盖配置的域名/IP。CSR 的签名与本地私钥必须匹配；请求的 subject/SAN 不会被复制成额外授权。管理身份当前明确只接受 Ed25519 CSR。
- `controller/internal/enrollment`：管理 CA 在首次创建时签证/加密，然后在短事务中写入 CA 引用及 002 `credentials`。已有 CA 无法解密、凭据缺失/撤销、格式错误或私钥不匹配时启动失败，不替换 CA。CA 私钥通过注入 Cipher 的 `management_ca` binding 加密；公有证书可展示，私钥不离开 Controller。
- 入网 token 为 32 字节密码学随机值的 URL-safe 编码，15 分钟有效，预先分配稳定 node ID。保存摘要及经过 Cipher `certificate` purpose 加密的可恢复 token，后者只在显式生成/幂等重取材料动作中解密。普通节点/状态查询不返回 token、hash、密文或私钥。创建、重发、改名、移除、证书撤销均有 revision CAS 与服务器生成 scope 的幂等账本。刷新重取相同动作不会创建第二个节点；重发新动作保留 node ID、增加 generation，使旧 token 失效。
- token 消耗：事务外检查 CSR 并预签证；事务内重查节点、generation、token 失效时间/撤销、CSR 重放，并原子保存消费关联与唯一证书记录。并发同 CSR 返回同一已提交证书；不同 CSR 冲突。响应提交后丢失可用原 CSR 重取原证书，即使 token 刚过期也允许恢复已提交结果，但已撤销/已过期证书不可恢复。幂等重放不会重复触发身份变更/断线回调。失败事务不会留下半个节点、已消费 token 或半张证书。
- `agent/internal/enrollment`：本地首次生成私钥/CSR，身份目录 0700、文件 0600，拒绝符号链接、非普通文件、宽松权限、损坏或不匹配的身份；不自动覆盖故障身份。首次文件通过临时文件、fsync、原子 link 创建，更新通过 fsync/rename/目录 fsync。重启复用同一密钥、CSR、node ID 和 CA。调用者必须先取得已有 Agent 组件生命周期锁。
- Agent 的 HTTPS 客户端在发送 token 前执行正常 CA 链和 SAN 验证，支持额外核对预置信任 CA 的指纹，不使用 `InsecureSkipVerify`。**输入必须包含 CA PEM**；可另给 SHA256 指纹认证该 PEM，不实现仅凭指纹在线抓取未知 CA 的 TOFU。拒绝重定向，不把 token 放 URL。首次入网与后续带客户端证书的续期分离。
- 续期保留同一 node ID/密钥，不读取或修改业务 checkpoint。旧证书与当前 CSR 公钥必须相同；续期响应丢失会返回已提交的同一新证书。默认节点证书 30 天（可配置 1 小时至 90 天）。到期边界显式拒绝。撤销后可给同一未移除节点签新入网 token；长期离线过期也须管理员显式重新入网，不能凭过期证书续期。移除后的 node ID 保留墓碑，不复活。
- `controller/internal/control` / `agent/internal/control`：真实 mTLS WebSocket，固定子协议 `meshstrata.control.v1`，禁用压缩，1 MiB 消息/帧读取限制（包含分片累计），只接受 text JSON，调用冻结 `internal/control.Decode` 验证版本、内外层/证书节点与 payload。Controller 只收 hello/result，Agent 只收 command/receipt；首条 Agent 消息必须 hello。ping/pong 只保活，无持续资源上报。Agent 使用带随机抖动的有界指数退避，可取消连接/退避，支持显式 Close/Reconnect。
- 移除/证书撤销提交后回调关闭旧控制连接；握手、路由、每条消息、投递和保活均核对证书与节点有效状态，并在注册连接后重查以覆盖移除竞态。服务端 Close 关闭并等待 WebSocket 生命周期。`Connected` 只在 hello 被接受后为真；可注入节点 DTO 的 control 在线字段，不改变 proxy verification。
- 结果仅在注入 `ResultStore.RecordResult` 返回提交成功后发 receipt。重放会再次确认但不重复推进账本。hello 的最多 100 个未确认结果也逐条先持久再 receipt；Agent 收到匹配 outbox 的 receipt 后调用持久确认接口，并继续发送下一批，已测 120 条恢复。Agent 的执行在串行 worker 中，消息 reader 保持运行，长命令不会阻断 ping/pong。
- 产物只由认证 node 经 `ArtifactResolver` 从任务账本定位固定 key，再经冻结 `ArtifactSource.Open(ctx,node,key)` 授权取回。没有任意文件路径读取；双方限制最多 16 MiB 并核对 SHA256。缺 B04 resolver/source 时，认证请求明确 501；无客户端证书先拒绝，不能用 cookie 替代。

返回明文缓冲按需清理；Go 密钥对象、字符串、运行时副本可能继续存在于堆内，不能承诺完全清零。测试使用 fake Cipher/Guard，不导入 B01 的实现；网络、证书、WebSocket 与 SQLite 测试实际执行。

## 固定构造与模块接口


`Options` 包含 `Context`、`Now`、`ControllerURL`、`ServerNames`、`CertificateLifetime`、`OnIdentityChange func(domain.ID)`、`ControlConnected func(domain.ID) bool`、`RelayAllowed func(context.Context,domain.ID) bool`。nil 基础依赖、无效 HTTPS 地址/寿命/SAN、不可恢复 CA 均返回错误。Repository 只持有 `storage.Database`，不打开连接、不访问 Store 私有 db，不向 HTTP 暴露 Queries；加密/签证/网络不在事务中，不嵌套单连接事务。

Options 的窄依赖：

```go
type Authenticator interface {
    Authenticate(context.Context, *x509.Certificate) (domain.ID, error)
}

    RecordResult(context.Context, domain.ID, protocol.Result) (bool, error)
```

`Authenticator` 注入 enrollment Service；`Results` 可直接注入现有 `*storage.Store`。`Recovery`、`Artifacts`、`ArtifactResolver` 由 B04 提供，不能把 nil 当成发布/恢复已完成。Deliver 只负责通道与基本消息验证，依赖图、阶段、串行调度、截止策略与最终发布属于 B04。

Agent enrollment Options：ControllerURL、CAPEM、可选 CAFingerprint、稳定 NodeID、Now。ControllerURL 不带业务路径，token 仅交 Enroll，不保存到普通配置或日志。

Agent control 的 `New(Options)`、`Run(ctx)`、`Close()`、`Reconnect()`、`DownloadArtifact(ctx,key,maximum)` 已实现。Options 包含 URL（wss `/control/v1`）、NodeID、动态 `TLSConfig func() (*tls.Config,error)`、Runtime、Now、退避/保活/写超时、可选 BeforeConnect。Runtime 必须由 B05 注入：

```go
type Runtime interface {
    Hello(context.Context) (protocol.Hello, error)
    Execute(context.Context, protocol.Command) (protocol.Result, error)
    Acknowledge(context.Context, protocol.Receipt) error
}
```

Execute 必须先通过 B05 的 LocalState 原子持久 checkpoint/tombstone/outbox 后返回 Result；Hello 只读真实持久状态，最多 100 个 pending；Acknowledge 只删除匹配 receipt。方法须响应 context 取消。Runtime 缺失时 New 明确失败，不制造 Applied/Verified 或内存持久化替身。工作协程会给 Execute 命令 deadline 子 context。

## I01 入口接线

1. 单次 `storage.Open` 后创建本模块 Repository，注入 B01 的 Cipher/Guard。Options.ControllerURL 使用实际 HTTPS 9443 地址，ServerNames 包含其域名/IP；Now 可用 time.Now。CA 缺 key/数据不可恢复必须阻止入口启动。
2. 声明 `var channel *control.Server`，构造 enrollment 时以闭包注入 OnIdentityChange（非 nil 时 channel.Disconnect）与 ControlConnected（非 nil 时 channel.Connected）。再 `control.New(Options{Authenticator:svc,Results:store,...})`。这两个闭包在全部构造完成后才开放请求，不在运行中改 Options。RelayAllowed 需由 I01 配置明确绑定 Controller 本机已注册 both Agent 和启用条件。
3. 管理 8443 注册 `svc.ManagementHandler()` 覆盖 `/api/v1/nodes` 与 `/api/v1/nodes/`，内部已按方法使用 Guard；不可只保护页面路径。
4. 9443 单独 HTTP server：`Handler:svc.NodeHandler(channel.Handler())`、`TLSConfig:svc.TLSConfig()`，以 `Serve(tls.NewListener(listener, server.TLSConfig))` 启动，建议 ReadHeaderTimeout=5s、IdleTimeout=1m、MaxHeaderBytes=16KiB。TLS 最低1.3、ALPN 仅 http/1.1。此组合只有精确 `/enroll/v1` 允许没有客户端证书；续期自己强制 mTLS，其余路径进入 control 前再次核对身份。不能单独把 EnrollmentHandler 挂进放宽的整个 `/enroll/` 前缀，更不能给 control 安装 cookie Guard 替代节点认证。
5. Agent 在已有独立组件锁内 `enrollment.Open(filepath.Join(stateDir,"identity"))`；原始入网动作提供预分配 node ID/ControllerURL/CA PEM/可选指纹和仅内存 token。成功后动态使用 client.TLSConfig，不保存 token。重启读取稳定身份并恢复原配置的 CA/地址；过期重新入网也使用同一身份目录，不删除 key/checkpoint。
6. Agent 有 B05 Runtime 后才构造 control Client，TLSConfig 注入 enrollment 客户端，URL 为 wss 控制地址。同一生命周期运行 `Maintain(ctx,time.Hour,7*24*time.Hour,controlClient.Reconnect,onStableFailure)`，同时可用 BeforeConnect 调用 RenewIfNeeded；持续在线也会定时续期。正式安装、信任资料传递、Linux 命令由 B17 完成，本模块不生成假安装器。
7. Shutdown 必须取消 Agent Run/Maintain，并调用控制 Client.Close；Controller 调用 channel.Close 关闭 hijacked WebSocket，再关闭 HTTP listener/Store。不能只依赖 http.Server.Shutdown 关闭已升级通道。
8. B04 注入 Recovery、ArtifactResolver、ArtifactSource，并将真实命令交 Deliver；B05 实现 Runtime 与 LocalState。移除任务按上一节特殊意图编排。未实现时维持明确依赖/待清理，不将控制在线等同代理可用。

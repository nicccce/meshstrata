## I02 构造与启动顺序

1. 建立各自的 0700 私有目录。先用 `runtime.NewProcess(runtime.ProcessOptions{Binary, WorkDir, ConfigDir, StateDir, StopTimeout})` 访问受管实例状态。传固定 Linux amd64 的 Mihomo v1.19.33 二进制，摘要 `19cbe7ba1523a92ed2d0a30716ea093de57db05b7844db23de2b9c21fd7a1afa`。Process 需要 Linux `/proc` 和 pidfd。为管理 socket 留出独立 0700 父目录，并保持短的绝对路径。
2. 使用独立节点密钥打开 `checkpoint.Open(checkpoint.Options{Dir, NodeID, KeyID, Key, Now})`。Key 恰为 32 字节，KeyID 为 1 至 128 个字母、数字、点、下划线或连字符。目录专供检查点和已认证的原始包。使用固定配置目录、管理 Unix socket 和本机随机 API secret 构造 B03 `mihomo.New`，TCP 管理地址留空。I02 遇到检查点打不开的情况，应调用已构造的 Process 的 `Stop` 后拒绝启动业务控制连接，使无法读取账本的实例停止继续使用历史授权。
3. 调用 `authorization.NewResolver(nodeID, configDir, []authorization.Material{...})`。每项包含 `Ref control.LocalMaterial`，TLS 项只填 `Path`，须在私有 `materials/` 子树下，文件为 0600。REALITY 项只填内存里的 `Value`，为未填充的 URL-safe base64 X25519 私钥。构造 `runtime.NewProbes(runtime.ProbeOptions{Binary, Dir, Materials, Timeout, Random})`，Dir 专供短期本机客户端。使用 `ForwardFactory` 和 `RevocationFactory` 方法值连接 Runtime。转发目标由探针按需绑定本机数字回环地址。
4. 使用阶段二固定字段构造 `runtime.New(runtime.Options{NodeID, State, Fetch, Materials, Kernel, Process, ProbeFactory, RevocationProbeFactory, Now, Random, OnPending, ConfigDir, SocketPath, APISecret})`。State 使用 B05 Store，除根 LocalState 外提供 `SaveArtifact(ctx,key,bytes)`、`ReadArtifact(ctx,key)` 和 `RestrictionResults(ctx)` 供恢复及去重。自定义 Store 也须实现这三个方法。Kernel 直接接 B03 Adapter。Fetch 闭包接后续创建的 B02 `Client.DownloadArtifact`。OnPending 是无参的短回调，接 `Client.Reconnect`，由 Runtime 在原子提交后的独立通知协程调用。
5. 构造 B02 Client 并注入 Runtime，启动 `Runtime.Run(ctx)`，等待 `Ready()` 或 Run 错误。恢复成功才启动控制连接。B02 消费 `Hello(ctx)`、`Execute(ctx,cmd)`、`Acknowledge(ctx,receipt)`。关闭先停止 B02，再 Runtime.Close，最终 Store.Close。正常退出时保留独立 Mihomo 进程。Ubuntu/systemd 若将 Agent 子进程纳入同一 stop cgroup，I02/T02 须验证阶段一服务配置的停止行为。B17 的正式服务应让 Mihomo 在独立服务生命周期内运行，不能仅依赖 setsid 跨越 cgroup 清理。

## 持久与执行边界

- Store 以私有目录描述符操作，拒绝符号链接、非直属私有路径、跨 UID 的可写目录、硬链接和非 0600 文件。AES-256-GCM 随机 nonce 的 AAD 同时绑定节点、key ID、格式和用途文件名。持锁 CAS 原子替换单一密文状态文件，完整保存五阶段指针、时钟下界、epoch、原授权、墓碑、命令身份、LastResult 和未回执结果。另保留每个受限身份最近的清理进度，回执只删除精确 outbox 项并前进 CAS。
- 每次写入先同步新文件、原子 rename、同步父目录，再以同样顺序更新经认证的修订高水位。rename 前中断保留旧文件，两个文件更新之间中断时，已同步的新状态可推进旧高水位。旧状态低于已提交高水位、标记存在而状态丢失、坏版本、坏标签、错密钥均拒绝。同步结果不确定时当前 Store 停止接受后续操作，要求重开恢复。单机本地账本依赖受信设备及服务 UID，整目录连同高水位被同权限主体恢复为历史镜像，无法由本地密文识别。
- 命令从公共控制层校验后以 1 MiB 上限 DecodeBundle、BindCommand。持久接纳身份和高水位，原始包密文按摘要落地。权限从独立账本合并，旧快照只消费已有授权。同 identity 的 Listener、有效期、代次、凭证字段不可改，续期需要新 identity/凭证及更高代次。撤销、到期与当前激活共用逻辑时钟和永久墓碑，旧 artifact 不会恢复失效权限。
- 候选由强类型 B03 Generate 产生，以实际字节 SHA-256 定名。候选文件 0600、同步并通过 Validate 后记 Candidate，启动或重载后记 Applied 尝试。检查进程归属、Unix API 对端 PID、真实监听和流量后，原子更新 Verified、Startup、PreviousGood 和结果。Hello 携带经确认修订的 artifact 摘要，Restriction 携实际有效字节摘要。格式 1 的 REJECT 规则若令真实业务回显不可达，当前结果会保持未验证或执行失败。
- 长时下载在内核激活门之外。独立时钟约每 250ms 检查一次并用持久 ClockFloor 抑制回拨；有活跃授权时约每秒持久推进时钟。到期先同步墓碑和原任务 pending 证据，取消候选，精确重载撤销并按 inboundName 与连接 ID 清理。候选未及时让出激活门、PID/会话归属不明或无法确认已关闭时，只停已认证的本平台实例。清理确认另用新序号，单事件最多 32 条，每个 origin 独立；超时和探测不全保留待确认。临时 UDP 出站 socket 也会呈现为 `/proc` UDP state 07，使用已归属的预期监听和旧端口明确拒绝验证撤销。
- 启动采用进程以启动意图的私有 token、boot ID、PID、启动 ticks、固定二进制 inode/dev 和 argv 共同标识；仅经 pidfd 信号停止。崩溃落在已写 intent 和 PID 之间时，可按精确启动身份找回。恢复先过滤 Startup，能确认同一监督实例、且有效字节与已验证快照一致时直接复检。Candidate 与 Applied 不一致时停止不确定实例，再按持久 Startup 恢复。失败回滚重新过滤、校验和验证；回滚失败清除 Verified 并停止已归属实例。
- 探针实际启动独立固定内核，使用受限回环 SOCKS5 和独立 TCP、业务 UDP 回显。SS2022、Trojan、VLESS 的负向比较使用正常凭据成功和新错凭据下的可观察闭合；Hysteria 2 另启全新的 QUIC 客户端，要求明确认证拒绝。旧端口移除要求明确 TCP/UDP 拒绝或同端口新传输认证拒绝。已跟踪旧会话按连接 ID 清除，并复查保留身份。共享 Listener 仍需额外适配，不能归属旧会话时会走受管进程停止路径。

## I02 与 T02

I02 需要实现独立节点 key、受限材料注册、短路径和 API secret 的配置或 CLI 供给；审阅连接回调和服务生命周期后才启用业务 Agent。检查点会保留永久授权和执行账本，密文状态超过 256 MiB 时明确失败并进入保护状态；现有版本未实现渲染及密文产物的垃圾回收。生产默认只接受上述 amd64 资产，其他架构需要 I02 补独立摘要后再启用。

T02 在 Ubuntu/systemd 和 Alpine/OpenRC 的真实 Controller 与 Agent 组合上，复测公网双拓扑发布与业务 TCP/UDP、节点与凭据绑定、错认证、Controller 断连后本地到期及回执排空、Agent 真进程崩溃/重启、候选及重载阶段异常、独立身份存量连接、外部端口占用、正常回滚及回滚失败、旧 epoch/旧快照/删除与到期竞态、回拨及重入网。额外检查真实的 TLS 信任与公网 正常发布路径、IPv4/IPv6 双栈、透明代理共存、故障重连后的 Release ledger 和资源回收。验收须核对正式平台 init 在 Agent 重启时保留安全 Mihomo 生命周期，以及精确停止时仅停止受管实例。

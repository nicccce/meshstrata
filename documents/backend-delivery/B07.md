
- `db` 为唯一 Controller `storage.Database`。进程内 `stage3.Rules` 和 `stage3.ClientBuilder` 签名未改。额外的管理读接口 `(*rules.Service).DomainSet(context.Context, control.Pin) (stage3.DomainSetSnapshot, error)` 按全 Pin 读。B08 以 `Profile(ctx, pin)` 取不可变版本；校验订阅和入口当代授权、从 B01 按用途/引用/接收方获取明文，并在生成完成后重新核对授权和修订。生成器无时钟，不判断当前过期；冻结的 `control.PrivateCredential` 无 purpose、entry ID、generation 或 grant，因此受信的 B08 投影仍是鉴权边界。单独的 `EntrySecret` 形状校验不能证明其来自 B01。
- 管理写动作在 Guard 后调用；幂等作用域为本 Controller 的唯一管理员 × 操作。键从请求取，作用域由服务固定；未来若支持多管理员，需要把认证主体以受信参数或 context 接入并扩展 009 的作用域约束。成功记录与版本一起原子写；重放先查账本，CAS 失败不写账本，旧结果不跳至最新头。ID、摘要和入库内容在写事务外准备；回调只查写当前事务的 queries。
- I03 给管理 HTTP 定义明确 DTO，投影只需实体/全 Pin、规则文本编辑字段和已有的安全 Issue。冻结 `Preview.Groups` 只有选中的 entry ID 与组名；如果 UI 要每组成员，建议另增安全投影 `PreviewGroup{Name string, MemberEntryIDs []domain.ID, SelectedEntryID domain.ID}`，沿订阅顺序派生。列表、名称/原文的管理读、删除和订阅引用释放没有冻结方法；请 I03/B11 为其设独立鉴权、CAS、分页及依赖检查。已引用版本由 FK 保留；不能绕过订阅或旧 Profile 引用删除。
- 输出 `stage3.FullConfig` 和 `stage3.ProxyProvider` 各自只交对应下载通道。两者均含入口私密凭据，不能挂在普通管理预览、日志或任务证据上。Preview 可接受未分配端口的 `pending` 草稿并给 `ENTRY_NOT_CONFIRMED`；正式生成只接受 confirmed、未撤销、无清理的绑定。两种下载都检查规则方案、条目作用域和 DNS 计划；输出上限各 1 MiB。provider 只含 `proxies`，使用者需自行配置策略和业务 UDP 防护。

## 规则与 009

将 [B07.sql](../../controller/internal/storage/proposals/B07.sql) 审入为 `009_b07.sql`，保留正式 001–007，安装后用 [b07_rules.sql](../../controller/internal/storage/queries/b07_rules.sql) 生成 dbgen。提案沿用 002 的 `rule_profiles`、`rule_profile_revisions`、`rule_lines`、`rule_domain_sets`、`domain_sets`、`domain_set_revisions`、`domain_set_members`，订阅现有 Profile FK 可直接使用。新增成员顺序、规则源码位置、`b07_domain_pins`、`b07_profile_pins`、`b07_profile_set_pins` 和 `b07_mutations`。引用同时匹配旧关系的精确修订及 B07 的精确摘要。存量行、外键和顺序未知的旧成员保留；没有 B07 Pin 的旧修订拒绝作为下载快照，需管理员审阅后显式保存新修订。不存在对 008/010 新表的依赖。依赖提案精确为 `golang.org/x/net@v0.51.0` 与其 IDNA 所需的 `golang.org/x/text@v0.34.0`。

支持裸逐行 CSV 风格规则或唯一顶层 `rules:` 的同缩进列表。允许完整行注释、CRLF 和简单引号包裹的单行标量；不解释 YAML 转义、别名、标签、流式结构、任意顶层字段。上限 128 KiB、8192 条；诊断含 1 起始行与 UTF-8 字节列，只带安全路径/代码。单 MATCH 原样提取目标、移动至末尾；无 MATCH 报 `MATCH_REQUIRED`，多个报所有 `MULTIPLE_MATCH` 行。支持 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6、RULE-SET、MATCH，唯一可选参数为 CIDR 的 `no-resolve`。目标使用稳定 route ID、`All-Proxies`、真实 `ExitGroupName`、显式内建目标。方案名与组名不作模糊匹配。

DomainSet 用显式 IDNA Lookup 转 ASCII、再按 `control.DomainName` 校验，拒绝数值 IP（含常见旧式 IPv4 拼写）、通配符、URL、逗号和非域名输入；规范化去重按首次出现保序。每集合最多 4096 项；每方案最多 128 个集合，成员合计规范域名文本 ≤128 KiB。RULE-SET 的值是稳定集合 ID；输入 `Sets` 必须提供实际使用集合的全部 Pin，同一 ID 不得混用版本。Profile 归档该修订的引用和成员顺序，读取时从同一读事务重建，并在事务外校验全 Pin 和结构；版本更新后旧方案仍读相同成员。规则编译复用同一份规范快照，不将原文塞进 YAML。

## Mihomo 与 DNS 的可生成范围

固定为 B03 的 Linux amd64 Mihomo **v1.19.33**。输出 JSON 形式的受限 YAML，可由锁定内核读取。只从订阅入口映射公开 host/port/SNI/REALITY 公钥字段及该条目的密码或 UUID；不会投影内部 hop、下游拨号 IP、出口认证或 Controller/download 数据。Trojan 和 Hy2 校验证书链及名称；冻结 `ProxyEndpoint` 没有 B03 测试所用的叶证书 pin。I03 要么给对应入口使用客户端已信任的证书，要么在 `control.ProxyEndpoint` 增加经严格校验的 `TLSLeafSHA256 string` 并绑定 route/lease 摘要，渲染为 Mihomo `fingerprint`。不能改成跳过证书校验。VLESS 生成 REALITY/Vision，SS2022 生成固定 cipher 与 PSK，Hy2 保留外层 QUIC。

B08 需明确供给偏好和三组数值 DNS；例如 `Mode:"tun", AllRoutesGroup:true, GroupByExit:true`，IPv6/BusinessUDP 为 false，`Bootstrap:["1.1.1.1"]`、`ProxyServers:["https://1.1.1.1/dns-query"]`、`Business:["https://1.0.0.1/dns-query"]`，配显式 `MATCH,All-Proxies`。这些是接线示例，生成器不补硬编码服务器。两种分组选项独立；按订阅顺序生成非空手动 select。 `default-selected` 使指定成员无需重排；锁定版支持 `empty-fallback: REJECT`。同名 Exit 组一旦出现策略 ID、修订或摘要不一致即冲突；同末端不同策略 ID 分开。应用层 UDP 默认以首条 `NETWORK,udp,REJECT` 拒绝，和 Hy2 外层 UDP 分开；启用业务 UDP 要所有路径的冻结 UDP 开关及已验证证据、TUN 模式且无 IP 类规则。System Proxy 只开本地 mixed port 并提示 `LIMITED_COVERAGE`；不承诺防火墙、IPv6 拦截或系统应用全接管。当前快照无逐跳 IPv6 业务能力，`IPv6:true` 和 IPv6-only 公网入口拒绝；IPv6 CIDR 可作为明确的 `no-resolve` 字面量规则保存和编译。

1. **客户端业务 DNS**：Mihomo `nameserver-policy` 与 TCP 规则共用域名条件、纯域名 inline RULE-SET。DOMAIN-KEYWORD 用只含该关键词条件的 inline classical DNS matcher。实际查询为数值 HTTPS + `#All-Proxies`、`#Exit-…`、显式选中的且可安全表示的单代理名或显式 `#REJECT`。无业务 DNS fallback 或动态 `respect-rules`。冲突的精确/后缀/集合重叠拒绝；关键词与另外的显式域名目标不同则保守拒绝。域名规则或 MATCH 选 DIRECT，或 route 名含空白、标点等不能安全放入 DNS dialer fragment 时拒绝。明确 `no-resolve` 的字面量 CIDR 保持原顺序并提示 `DNS_EGRESS_NOT_INFERRED`；可能触发客户端提前解析的 CIDR 或与业务 UDP 同开的 CIDR 拒绝。进程/端口等尚无可推导的 DNS 策略，语法明确不支持。
2. **代理域名的自举**：单列数值 `default-nameserver`；`proxy-server-nameserver` 仅允许数值 UDP 或无 query/fragment/认证的数值 HTTPS，显式 `#DIRECT` 只出现在这条启动路径。关闭系统 hosts、业务 DNS fallback、H3 DNS 优选和隐式健康测试组。自举失败没有改走业务 DNS 的配置分支。
3. **业务目标域名与服务端**：TUN fake-IP 将域名绑定到后续流量，禁止客户端 CIDR 规则要求先解析；TCP 由入选代理携带域名。中间段保持域名、末端按固定 DNS 与出口规则解析和转发是 B06/I03 的服务端契约。自定义多目标策略下，业务目的地址和 DoH 上游 IP 可能命中不同规则，Preview 提示 `DNS_TERMINAL_EGRESS_NOT_CHECKED`；客户端编译不能证明终端公网出口同源。手动组切换也不保证存量连接、真实 DNS 缓存或持久 DoH 连接立即切换。

锁定版字段核对：[配置和 DNS 策略](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/config/config.go)、[DNS dialer](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/tunnel/dns_dialer.go)、[DNS resolver](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/dns/resolver.go)、[手动选择](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/adapter/outboundgroup/selector.go)、[内联规则 provider](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/rules/provider/parse.go)。

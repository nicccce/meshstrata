## 管理和本地信任边界

准备配置由管理员经登录、Origin/CSRF、节点 revision CAS 提交，包含带完整 Pin 的 DNS/socket/pool，不由管理员填写观察结论。可信节点本地 provisioning 限定 DNS、socket、批准出口地址、数值 canary 与保护拓扑。发布导致节点 revision 增加后，后台以新 revision 请求真实库存；曾已观测且仍被策略引用的出口也重新探测。未探测新目标不会自动获得信任。TCP 短期成功与业务 UDP 分开；后者保持 `not_checked`。

TLS/REALITY 材料使用 `import-materials` 本地 stdin 导入已批准的 LocalMaterial 引用，私有目录/文件、用途与内容检查、同内容重放、不同内容拒绝覆盖。业务 leaf 不接受 CA 证书。HTTP 不接受文件路径、管理密钥或任意探针地址。HTTP/SOCKS5 凭据专用写入，目的地仍受本地批准；密文、目标修订与幂等回执同事务保存，重复请求核对实际原凭据。

`controller/internal/business` 以专用 DTO 提供线路保存/校验/发布/历史、规则与域集合保存/复制/诊断、出口目标/策略与认证、节点准备/观察/显式 drain/switch，以及订阅创建/配置/预览/续期/删除/重置链接/显式规则采用。管理输出排除 Bundle、Tail、私有计划、代理密码/UUID、credential ref、下载 token/URL。专用 Copy URL POST 使用管理员和 Origin/CSRF；完整配置与 proxies-only provider 是不同 HTTPS 路径。

所有新写接口限制请求大小并拒绝重复/未知字段、尾随数据和查询参数。资源和引用列表默认 50、最大 200，opaque cursor 绑定类型/对象；线路历史按 revision 倒序分页。业务错误使用安全 code、revision 和明确诊断位置。202/pending 不代表已验证。

外层 dispatcher 在 ServeMux 规范化之前隔离敏感命名空间。错方法、畸形路径、编码变体和查询参数拒绝，无重定向；成功及错误均 no-store/no-referrer。下载逐次检查当前订阅和节点有效性。反向代理部署仍须在 URI 清洗、访问日志和重定向之前遵守相同隔离。

## 持久执行与资源引用

Controller 随 HTTP/B04 同时启停唯一业务 worker，退出等待取消和 WebSocket 关闭后才关闭 DB。持久发布/订阅意图、真实 B04 task 与 cleanup 是事实来源。worker 分页、公平游标、单项超时、有限退避元数据；一个失败项不会阻止后续项扫描。Controller 重启后继续收敛。断线期间已密封但未接纳的入口计划可能被其他任务推进节点 CAS；重试先查询原任务，再重编译当前基线。011 保存各候选密文，任务事务检查当前计划 digest，且重新编译事务排除已接纳任务，避免覆盖丢失响应或让旧提交者晚到接纳。退避日志在安全错误码变化时更新。已确认本地到期撤销可作为当前基线继续清理：必须匹配当前 effective digest、真实已确认 restriction 回执及全部相关 Grant 的 cleanup 确认；pending/不匹配证据仍拒绝。提交事务再次检查基线摘要，防止编译期间发生撤销的竞争。

归档保留历史 Pin。服务安装新修订/依赖的实际事务再次检查归档，防止 HTTP 预检后的竞争。固定旧版本的订阅仍参与规则/出口依赖分析；推进目录 head 不能隐藏旧引用。最后线路引用退休后才创建独立内部 link cleanup，真实确认前不释放端口，不用入口身份冒充内部清理。预览添加末端策略使用独立 slice 并排序，避免改变共享基线和产生不稳定产物。

新增正式 `011_i03c.sql`，001–010 文件名和字节保持冻结；后续 B09–B18 的预留槽顺移为 012–021。迁移回归从真实已填充的旧账本验证升级、失败事务回滚、重启及旧密文/任务/不可变 Grant 保留。

复现驱动为共享 loopback 上的全部节点分配互不重叠、避开系统临时源端口范围的 TCP/UDP 检查后监听池。探测子进程的启动与 Wait 由专用锁定 OS 线程拥有，防止 Linux Pdeathsig 在调用线程退出时误杀仍在转发的客户端；Agent 实际退出时仍自动终止探测进程。回归强制调用线程退休，旧实现不到一秒即失败，修复后要求真实 SOCKS/TCP 回显。探测次数、时限与正反认证门槛保持原值，未采用试验性的延长时限或退避。 探测客户端还需经自有 loopback TCP 端点的实际回显确认转发引擎已就绪；只允许这一准确地址/端口的 DIRECT 启动检查，并明确排除实际验证目标。真正的 canary 始终走 selected，另有真实反例证明选定出口失败时不能借启动检查绕行。该屏障对应锁定内核在[创建监听后才切换 Running](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/hub/executor/executor.go#L101)，且[未 Running 时关闭 TCP 流量](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/tunnel/tunnel.go#L473)的顺序。固定失败诊断不记录 payload 或凭据。连续重载复现的四个共享订阅和两轮认证 HTTP/SOCKS5 出口通过；不据此宣称大规模负载稳定性。

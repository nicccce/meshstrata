## B06：固定线路、出口与发布

1. `SaveDraft` 保存有序 `HopDraft`（唯一 node、最多 8 跳），端口 0 为已选协议的池内分配请求；`ValidateDraft(pin)` 只读，返回固定顺序、阻断项、提示。端口及 DNS/节点 SocketSpec 由 `Infrastructure.NodeSnapshot` 的固定 Pin 和池范围来；节点协议可用/业务 UDP 观察分别校验，反向 frp 的实际执行仍阶段五。在本阶段只支持明确用户选定的线路；不扫描、不替换节点、协议或目标。
2. `PublishDraft(mutation,pin,deadline)` 再查审阅 Pin 和依赖；从末端到入口计算真实后缀、固定端口、保留新/重用资源，再交 `SubmitV2`。底层继续使用 B04 的节点 CAS、DAG 与结果账本；`ExpectedRevision` 是当前节点修订，目标为 +1。B06 模板的 TaskID 留空；网关填真实 ID 后才编码。依赖关系为入口等待下游；若下游不变，须校验它当前的确认摘要与对应后缀，避免发往旧的同端口。所有模板含该节点完整期望配置，包括保留的其他线路；保留多条策略的不同固定版本，不在同一个规则或出口组内混用。
3. 线路发布不等于发放入口。无订阅的单节点线路可先提交无授权 Listener 的末端策略准备产物；只在网关确认配置后推进线路指针，公网转发保持 `not_checked`。多跳可以分配真实内部 Listener 供 DAG 验证；禁止为使 B04 接受而伪造客户。HTTP 202 仅任务接收；调用 `ReconcilePublication(ctx,taskID)` 对账，只有 `ReleaseState=published` 且任务对应审阅版本，才推进已发布头。失败、未完成回滚或超时保留旧头和失败草稿；旧版可按 Pin 读至引用释放。已有 002 `route_revisions.entry_listener_id` 不可空，008 用独立规范化版本/跳段/头表和真实 `routes.id` FK 表达无入口线路；B08 继续用 002 的 route FK。不填伪造 listener，不把新指针冒写到旧 `routes.published_revision`。
4. `PublishedRoute.Pin.Digest = stage3.RouteDigest(view)`（名称、具体完整 Tail、是否节点默认出口；不含观察和任何凭据）。第一个 Hop 的端口为线路审阅后的基线，条目入口只按授权后的 `IngressLease.Endpoint.Port` 替换；`ApplyEntry` 接 B08 固定线路和租约，不能按名字/当前发布头重新解析。旧已发布线路的修改可保留活跃订阅原 Pin；切到新 Pin 是另一次审核、发布和入口变更。
5. 内部共享键为 `RouteTail.Key()`，按**完整下游后缀**（本接收跳开头、每跳节点/协议/外观参数/具体端口/固定拨号 IP/节点配置/DNS、业务 UDP、固定末端策略）匹配。端口可从已使用候选取，但只有键完全相同并未退休时可共享。新分配仅用池/显式端口并按 `ReserveLink` CAS；固定端口冲突报错，自动选择只在有界池试候选，不扫描网络。008 用独立内部资源身份、凭据 `internal_proxy`、真 listener 与唯一 suffix key 及真实版本/任务引用；入口凭据 `proxy_entry` 单独建。重复请求用相同 OperationID 与同一 payload，租约与引用重试幂等。只有最后一个引用移除、持久退休且实际清理确认时才释放端口；离线 Pending，失败/回退不清理仍被引用资源。网关串行校验两类端口账本与双栈重叠。
6. `Egress.SaveTarget/SavePolicy/Policy` 声明的目标限定 `node_default/interface/http/socks5`。出口口令单独使用 `EgressProxy` 的绑定加密，008 用自己的密文表和真实目标版本 FK（不扩大 002 CHECK、不能借用其他用途）；旧列与新存储不得混淆。管理 DTO 不返回密码。目标快照 Pin 的 payload 为 `EgressTarget`；策略 Pin 的 payload 为 `EgressSpec`。目的单 IP 入库前规范为 /32 或 /128，有序首匹配，唯一末尾 MATCH；新自定义策略默认 MATCH → nil/REJECT。明确 Node Default 的固定策略可配置 MATCH → 固定 node_default Pin，不使用隐式回退。无效或不可用目标只让匹配流量失败；不重试后续规则/出口，不自动更换 DNS。UDP 白名单按全链路与目标实际能力检查，默认拒绝业务 UDP。Hy2 外层始终 UDP。
7. 终端代理主机名与数值拨号 IP 一起固定，Controller 使用显式 bootstrap 证据而非发送任意 URL，渲染器只拨固定 IP。Controller 按拓扑已知端点，Agent 按当前/候选监听、真实本地接口/地址、私有 API、TUN/fake-IP 网段等填 `LoopInventory`，调用 `CheckEgressLoops`，还要检查出口网卡存在且非受控 TUN、地址新鲜、实际下游不会绕回。库存缺失或无法证明安全隔离时禁止应用该配置。不得将 DNS 逻辑主机名再交内核改拨未校验 IP。运行环境的外部代理、网卡转发和公网行为留 `Not Checked`，结构通过不等于探测通过。

脱敏数据流示例：线路末端为 C，尾链 `[B/SS2022:32001, C/Trojan:32002]` 与 `[B/SS2022:32001, C/Trojan:32002]` 只有 DNS、绑定及固定出口版本也相等才可共享；C 的出口规则版本从 4 改 5 时两条相关后缀都变。某订阅取得独立 A:32100 与 generation=1，无论其他订阅是否复用 B/C，撤销只移除该 A 的入口与自己的资源引用。

## B07：规则与两种生成物

`SaveDomainSet` 接标准小写 ASCII 域名（可先显式 IDNA 规范化）；用 `control.DomainName`，拒绝 IP/通配/URL/逗号。DomainSet 与 Profile 的 Pin 分别 hash `DomainSetSpec` / `ProfileSpec`，规则解析后保序。规则文本最多 128KiB，仅明确支持一个 rules 段或逐行片段，不接任意 YAML 指令；保存失败返回行/列和稳定代码。至少支持 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR/IP-CIDR6、RULE-SET、MATCH；实现应拒绝未实现种类和选项。RULE-SET 绑定 DomainSet 的全 Pin，在配置中以纯域名 inline 数据生成（不拉远程 provider）。已有一个 MATCH 可提取目标，规范化到末尾；多个时报各行，要求管理员选。无 MATCH 的草稿要求显式兜底选择，生成结果始终只有一个末尾 MATCH。名称存在不等于该订阅能生成该组，按输入快照检查。方案编辑只影响加入其新 Pin 的下载配置，不重写服务端路径。

`Preview(ClientSnapshot)` 可在审批前计算分组/错误，返回无秘密结构，不生成可用的配置。“All-Proxies”/“Exit-*” 为非空手动 select，稳定名用 `ExitGroupName(terminal,policy)`；明确 Node Default 时 policy 参数用空 ID。同组 Validate 要比较完整策略 Pin，不能把不同策略版本混在同名组内，顺序按订阅顺序，只选有效成员。不插 `DIRECT` / `COMPATIBLE` 兜底、自动测速或自动切换；固定版本支持时设置 empty-fallback REJECT。B08 的初始默认项是两个分组选项开、TUN + fake-IP、IPv4、拒绝业务 UDP；System Proxy 标覆盖受限。默认在用户规则前加 `NETWORK,udp,REJECT`，它不禁止 Hy2 代理传输 UDP。

`BuildFull(GenerationInput) → FullConfig` 生成含 TUN/DNS/proxies/select/rules 的 Mihomo 完整配置；`BuildProvider → ProxyProvider` 只输出 proxies，不含组、规则、DNS 或下载 token。每种上限 1MiB；`ValidateGenerationBinding` 复核固定线路摘要、入口参数、独立 entry/identity/credential ref、同订阅 audience 和无撤销/未确认条目；B08 仍要做每次当前授权检查。两种生成物只含该订阅的公开入口与其凭据，不能带中转、Controller、其他订阅或外部出口的凭据。生成过程离线、不读文件或网络。

DNS 三层：①客户端业务 DNS 随域名规则/固定方案选真实 `#Exit-*` 或 `#All-Proxies`，使用明确的数值 HTTPS 上游，不把规则匹配失败变成直连。进程/IP/端口类只能提示 DNS 出口不可推导；重复和冲突域名要显式审核。②目标域名尽量原样透传到末端，中间节点不抢跑解析，末端用固定节点 DNS；CIDR 解析尊重 `no_resolve`，目标查询的上游连接按指定末端策略处理，必须有可解释的目标/DNS 同源约束，不能把“规则不同却共用一次 DNS”写成已证。③客户端代理服务器域名只走独立的显式数值 bootstrap，验证 TLS/REALITY，节点间/外部代理拨固定 IP，不从业务 DNS 自举，不让隧道解自己的地址。若锁定内核不支持所需 DNS 隔离，拒绝发布该组合，保留 Not Checked，不生成会绕行的成功配置。

## B08：条目、授权和下载

- `Create/UpdateConfig/Renew/Delete/ResetDownloadToken/Get` 输出安全管理视图，包含固定方案/路线 Pin、各条目的 generation、期限、同步/清理状态，绝不输出可恢复 token、URL 或秘密引用。活跃快照每订阅最多 128 条、每线路唯一一条，B08 保管 entry/identity、期限、代次、撤销与密文。入口不可变：延长到期亦分配新 generation/identity 与凭据（现有 CheckGrant 不接受原身份修改期限）。软到期保留原身份墓碑；可对尚未删除的条目续期，显式删除后的旧条目/身份均不可复活。
- B08 首先在短事务持久化操作意向、`ProxySecret` 的严格私有 JSON 密文及新身份参数，不先插缺 listener FK 的 002 关系行。调用 B06 `ReserveIngress`；B06 交 I03 网关，物化真实 listener + 端口租约、用请求摘要验证可重试。B08 CAS 提交真实 `subscription_entries / entry_identities` 与固定 Pin 的侧表、意向及引用；到期或删除 CAS 失败就不会发布。然后以相同 OperationID 调 `ApplyEntry` 写 B04 任务；`EntryChange.Subject` 是 B08 派发的已审阅订阅 Pin，B06 原样传给 `PublishPlan.Subject`，I03 按意向记录核对。丢响应可重复 `Reconcile(intentID)`，租约释放需要确认从未武装/监听或真实 cleanup。网关在任务提交、武装前重新读取当代 generation/撤销/审阅修订；Agent 在执行、恢复与回退时用持久 tombstone/clock floor 拦截旧代。B08 只在精确任务发布确认且最新授权仍有效时更新可下载快照；发生失败不泄露未确认入口，旧已确认且仍有效快照可保留。离线删订阅即时使链接失效，节点 Pending 直到真实拒绝证据，端口不提前释放。
- `DownloadLink(ctx,id)` 只能由 `Guard.Write` 包装的 `POST /api/v1/subscriptions/{subscription_id}/download-link` 调用（管理员 + Origin + CSRF），用已验证的 HTTPS `PublicOrigin`，不读请求 Host。标准链接 `https://example.invalid/subscriptions/v1/config/<redacted>`，无需自定义 header；可选 Authorization 兼容入口只用同下载能力，不接受管理凭据或 query token。响应体是 `SubscriptionDownloadLink{DownloadURL}`，wire 为 `{download_url}`；响应包括错误均 no-store/no-referrer、无重定向；Copy URL 刷新后返回当前有效 token，重置才更替。入口秘密不因重置链接而变化。提供者下载单独走 `DownloadProvider`，不把标准 URL 变成 provider。
- 随机读至少 32 字节，以 raw base64url 定长表示；存独立 SHA256 验证值，版本/到期/撤销每次查。复制专用动作以同一引用与 `secretstore.SubscriptionDownload` 调 B01 Cipher 恢复 raw token，并重校验 hash/version。010 采用独立用途受限 envelope 表 `subscription_download_credentials`（ID、subscription FK、version、key_id、ciphertext），`subscriptions.download_token_credential_ref` 指向该表；同一 010 事务约束指针归属与版本，沿用 002 原 hash 列。先插新密文，CAS 更新 hash/version/引用并作废旧链接；专用表避免重建 002 credentials、重绑既有外键或破坏 CA。升级考虑已有 hash 无 recoverable ref：不得猜 token、不降级为 header-only，只有显式重置才创建新的可复制 URL。用真实既有 credentials + CA FK 升级 fixture 验证保留与 `foreign_key_check`。普通 DTO、草稿、错误、重定向、日志/HTTP access path/metrics 都不得含 token/URL。响应 payload 缓存只可在请求内；plaintext 使用后清理，日志用模板路径。
- `DownloadFull/DownloadProvider` 基于固定版本读有效条目，事务外解密/生成。开始和送出前重新核对 token hash/版本、授权与订阅/条目快照 revision，撤销/过期/变更期间生成的旧输出丢弃。从 B01 解密入口后，映射 `EntrySecret{IdentityID, Credential.Audience=SubscriptionID}`；该投影是进程内生成限权，不能序列化到管理 API。请求结束清除可清除的字节，禁止跨请求明文缓存。

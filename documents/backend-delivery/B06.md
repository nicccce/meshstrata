# B06｜线路、内部链路与出口策略

基线 `c46a256d457d33814567ab67272629e7766bed4b`，分支 `codex/bootstrap-controller-agent`。B06 只写自己的 Go、查询、008 提案和这份报告，无新依赖。现网仍为格式 1；这里的格式 2 计划是 Controller 进程内私有数据，不接普通管理 HTTP。

- `routes.NewService(stage3.RoutesOptions) (*routes.Service, error)` 实现 `stage3.Routes` 和 `EntryRoutes`。草稿按有序 1–8 个不同节点持久化，审阅重算固定 Pin，核对当前节点修订、SocketSpec、DNS、协议、已观测业务 UDP、末端策略与跨账本端口冲突。显式端口保持原值，0 仅试已选协议的有界池；审阅不写端口。反向 frp 拒绝。
- `PublishDraft` 持久化意向，末端向入口选定具体端口，生成完整 BundleV2 节点计划。现有授权、内部资源、各固定策略、退休记录和墓碑从节点基线保留；每个计划用当前节点 CAS、下一修订和即时 epoch，入口节点等待下游。无订阅时首跳只有审阅基线端口，不捏造入口 Listener 或授权；单节点可只准备末端策略。重用尾链要求完整后缀一致、有活跃资源记录，并核验当前接收节点基线的真实发布任务、修订和产物摘要。相同相邻节点或相同端口不够。
- `ReconcilePublication(ctx, taskID)` 将实际 `ReleaseState=published`、任务 ID、审阅 Subject、各节点应用时间及对应制品绑定一起核对。任务接收、观察到端口以及 Pending 均不推进头；失败、超时和回退保留旧确认头。响应丢失用同一请求或 `ResumePublication(ctx, operationID)` 重放同一密封计划，取回网关的真实任务 ID。`PublishedHead(ctx, routeID)` 给出新确认 Pin；`PublishedRoute(ctx, pin)` 始终校验指定历史版本的 `RouteDigest`，返回 `not_checked`。当前不 GC 历史快照。
- B08 推送真实 `EntryReservation`、`EntryChange`，B06 不读取 B08 表。入口绑定原订阅、线路 Pin、单独 Listener/端口/凭据和授权代；续期新身份不可复用旧凭据。入口发布重新验证下游的真实确认绑定，并将 B08 的 Subject 和 OperationID 原样传给网关。撤销/清理只匹配原身份、原订阅、原租约和原线路，不修改其他入口；真实授权局部状态仍由 B08/B04 对账。找不到原授权或墓碑时返回 `GRANT_ORIGIN_UNCERTAIN`，不猜测旧来源。
- `egress.NewService(stage3.EgressOptions) (*egress.Service, error)` 实现 `stage3.Egress`。目标与策略独立 CAS 和版本；策略选用真实同节点的固定目标。单 IP 规范为 /32 或 /128，规则首匹配，唯一末尾 MATCH；未选兜底就拒绝。显式 Node Default 是固定目标。匹配目标不可用不再尝试其他出口。HTTP/SOCKS5 保留逻辑主机名和固定数值 IP；对代理与接口组合要求当前、未过期的可信证据和完整回环库存，对候选及已保留的配置调用 `CheckEgressLoops`。业务 UDP 默认关闭；需要逐跳能力及末端正向证据，HTTP 出口不提供此能力；Hy2 底层 UDP 有独立的监听传输约束。

## 008 与接线

- [B06.sql](../../controller/internal/storage/proposals/B06.sql) 为新增迁移。版本/跳段/已确认端口与头分别写入 `b06_route_versions`、`b06_route_hops`、`b06_published_versions`、`b06_published_hops`、`b06_route_heads`；使用真实 002 `routes.id`，不写旧 `route_revisions.entry_listener_id` 或 `routes.published_revision`。`b06_publications`、`b06_publication_nodes` 保存意向、实际任务 FK 和密封节点计划。`b06_ingress`、`b06_entry_plans` 保存 B08 来参、真实租约和入口计划，密封计划使用独立 `route_release_plan` Cipher 绑定，不放入旧 credentials。
- `b06_link_candidates` 在调用网关前保存候选密文；`b06_internal_links`、`b06_link_references`、`b06_entry_link_references` 绑定真实内部资源、原发布版本及入口引用。内部 Listener 与 `internal_proxy` 凭据使用已有 002 关系表和端口账本；保留一跳一个成功租约、OperationID 请求摘要、非过期型内部身份及“最后引用 → 退休 → 确认清理 → 释放端口”顺序。入口是 `proxy_entry`，走独立租约。
- `b06_egress_objects` / `b06_egress_versions` 持久化固定目标和策略，`b06_policy_targets` 固定同节点目标版本关系，`b06_egress_credentials` 使用独立的 `secretstore.EgressProxy` 绑定及真实目标起源版本 FK，未扩展 002 CHECK。保留认证限同目标、同端点内容；更换地址需要显式提供需要的认证。普通投影必须省略私有引用及明文。SQL 生成输入为 [b06_routes.sql](../../controller/internal/storage/queries/b06_routes.sql)、[b06_links.sql](../../controller/internal/storage/queries/b06_links.sql)、[b06_egress.sql](../../controller/internal/storage/queries/b06_egress.sql)。
- I03 用同一个 `storage.Database` 接两个构造函数。B01 的 `Credentials.Open(ctx, secretstore.Binding)` 供入口和内部凭据；出口认证由 B06 内部 `egress.OpenAuth(ctx, stage3.Runtime, secretstore.Cipher, control.Pin, domain.ID)` 解封。可信 Controller 入口可通过 `(*egress.Service).Target(ctx, pin)` 组装固定策略快照，HTTP 仍须使用单独 DTO。B06 操作域当前是 Controller 管理员域内的每种操作；冻结 `domain.Mutation` 没有多租户 actor scope，新增多认证域时须在适配层提供稳定作用域。
- I03 的 `Infrastructure.ReserveLink` 在事务外调用 `routes.PrepareInternal(stage3.LinkReservation, routes.LinkAllocation) (routes.PreparedLink, error)`；`LinkAllocation` 带精确 SocketSpec、节点 CAS、实分配 ID 和 Clock。事务内先重查当前节点/池及候选端口，再调用 `routes.ReserveInternal(context.Context, *dbgen.Queries, routes.PreparedLink) (stage3.LinkLease, error)` 原子创建或引用同后缀资源；共同 B04 账本需要继续识别它的 002 端口行。对于入口，`Infrastructure.ReserveIngress(ctx, reservation, publishedRoute)` 由网关串行物化真实入口 Listener/FK 及端口，按 OperationID 和摘要幂等。
- 在 I03 已确认无当前引用、已排除旧制品/回退需求的写事务中，调用 `routes.RetireInternalReference(ctx, q, operationID, now) (bool, error)` 和 `routes.DropEntryLinkReferences(ctx, q, identityID, now) error`。后者只用于真实入口清理完成或有确证从未 arm。离线保持 Pending；I03 给实际 cleanup 产物加入退休记录并保留墓碑。`routes.ConfirmInternalCleanup(ctx, q, linkPin, taskID, now) error` 只对 retiring 资源，在真实任务表的 cleanup/subject/revision/节点及 `applied && cleanup=confirmed` 证据吻合后释放端口，保存确认任务 ID。旧线路头、仍活跃的发布意向、入口与其他版本的引用均不能用该 API 提前释放。
- I03 的 `Publisher.SubmitV2(ctx, mutation, plan)` 要先按 B06 传入的稳定内部幂等键和计划摘要查旧任务（即使已过截止），然后对新操作在同一事务校验审阅 Pin、意向、端口、节点版本、epoch 和 B08 当前授权。真实 `TaskID` 由网关填写；模板留空，B06 只在纯结构校验的局部副本中借用合法节点 ID 满足冻结 codec 的形状约束。网关在提交与 arm 重查当前证据/授权，并对真实产物调用 `EncodeBundleV2`、`CheckLinkPair`。普通发布调用 `ReleaseState(ctx, taskID)` 回传完整结果；必须使用冻结格式的摘要和原任务 Subject。恢复 worker 可用 `B06ResumablePublications` 扫有限批次后调 `ResumePublication`；入口重放由 B08 持久意向驱动。

## 公共边界与后续

`NodeSnapshot` 仅能携带一个完整基础格式。空 V1 基线可作显式结构转换并保留墓碑；有 V1 Listener/Resource 的节点缺少固定 V2 路径、出口及归属证据，B06 返回 `NOT_IMPLEMENTED`，不能重标格式。I03 需接出完整、已确认的 `NodeSnapshot.Extended` 和其实际产物/任务账本，再允许向这些节点发布。固定 `SocketSpec.RequestedPort != 0` 时，现有 V2 codec 只允许同端口或真正的 pool SocketSpec Pin；独立多订阅端口需要网关给出真实的 `RequestedPort=0` 入口配置。若必须保留固定线路端口 Pin 同时变化入口端口，I03 需扩展 `SocketV2` 对入口分配意图的绑定，B06 不换原 Pin。

冻结的 `EgressTargetInput` 没有审批证据，`LoopInventory` 也没有主机名解析快照、外部路由结果或已验证网卡列表。I03 的可信库存/探测适配器先把原始逻辑主机名→固定 IP、数值 bootstrap、接口隔离和时效核对，再用短事务调用生成的 `(*dbgen.Queries).B06PutEgressEvidence(ctx, dbgen.B06PutEgressEvidenceParams) error`。键是节点与节点修订、目标内容摘要、DNS 摘要；业务 UDP 只有正向确认才置 1。B06 无证据、证据过期或库存不全即拒绝，实际节点的安全检查仍由 I03 的提交/arm 与 Agent 执行。不得让管理请求凭自身内容写这张证据表。DNS/业务不能一般性地推导相同公网出口；需要严格隔离但锁定内核做不到的组合由 I03 渲染器拒绝。

B06 只提供清理事务和证据门槛，不调度 B04、Agent 或公网探测。I03 必须把撤销先落 B08 权限和原代账本；B06 只接受完整基线里的真实旧授权或墓碑，无法证明 origin 时保留 Pending 并由网关按原制品恢复。I03 独占 008 安装、sqlc、构建、组合根、任务对账及 V2 协商；不把本轮业务编译当真实可用转发。

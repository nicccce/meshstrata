## 本地授权、checkpoint 与恢复

加密本地状态保留旧格式读取路径；升级到 V2 时先写有明确版本外壳的状态，再写版本锚点。即使在两步之间中断，旧二进制也不能把 V2 误读为空 V1；新二进制可从状态修复锚点。错误 key、缺少或变造的原始 source、未知版本和降级都失败关闭。

V2 Binding 永久保存完整 listener 与首次原始 Origin，并从对应加密 source 重新核对。复用身份、内部 Pin 或出口 Pin 必须保持完整私有绑定，包括凭据。入口墓碑、内部 retirement、clock floor、撤销结果和首次来源单调保留；旧 artifact、PreviousGood、重放和时钟倒退不能复活它们。内部 link 没有客户到期时间。

V2 使用原 B05 的串行任务门、独立到期执行、配置私有文件、精确 PID/Unix API/socket 检查、连接 ID 清理、真实认证探针及回退。每次应用/恢复都从原始 source 重新筛选当前授权；先干验证，再应用、流量验证，最后写 Startup/Verified/outbox。未确认的 candidate 不因重启成为 Verified。探针与应用都可被独立到期打断；慢出口观察不能占住激活门延迟到期。

## 有限渲染与真实观察

`internal/mihomo/routeconfig` 仅生成有限的类型：按监听选择规则；中转固定唯一数值下一跳和对应凭据；末端固定所绑定的有序 CIDR/MATCH/目标；未识别流量全局 REJECT。业务 UDP 未获实际证据时拒绝。adapter 独立检查有限字段、规则、目标、未使用 outbound、TLS 校验、通用入口/TUN/脚本等，V1 candidate 不能借字段启用 V2。

TLS 本地材料按节点/用途解析，并核对密钥对及审阅的 leaf SHA256。VLESS 使用固定 REALITY public key/short ID/SNI。实核发现 REALITY 的握手拨号也经过路由（[锁定版本源码](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/listener/reality/reality.go#L70)）；因此为它生成独立的有限 direct outbound，业务规则禁止引用它，全局仍 REJECT。握手目标必须是审阅的固定数值地址，复用实际回环保护；尚未解析的域名握手目标失败关闭。

Runtime 在验证和实际生效前读取当前库存：真实本地接口/地址、TUN/点对点接口和网段、精确拥有的内核 PID/FD/socket/API，再与可信本地 provisioner 的 Controller/mesh 保护拓扑合并。未知 IPv6 wildcard 双栈状态按保守方式保护 IPv4 别名。候选 socket 与已有 socket 都参与回环检查。缺少保护拓扑、错误接口或保护端点/网段均不能作为允许出口的理由。

认证报告通过 V2 `observe/observation` 传输，每连接最多一个待处理请求，期限最多 30 秒。wire 只携带请求 ID 与可选 target Pin，不接受 URL、host、接口、凭据或脚本。`Runtime.ObserveV2` 使用本地 `ObservationOptionsV2.Plan` 与独立数值 canary allowlist：

- 库存实际读取接口和拥有的进程 socket，检查锁定内核及本地材料，报告配置 Pin；协议库存的业务 UDP 固定 `not_checked`。
- Node Default/指定接口/HTTP CONNECT/SOCKS5 通过限时随机 TCP 回显生成观察，记录实际本地 source IP 和所属 up 接口。指定接口真实绑定设备；带凭据代理还须用新连接证明错误密码获得明确认证拒绝。网络超时不算拒绝成功。
- Controller 只接受当前 session 的关联报告，事务内再查 session、节点/DNS revision、target Pin、接口/source IP、独立探针白名单与短 TTL，然后调用 A 的 `RecordInventory/RecordEgressObservation`。断线报告、重放、过期或绑定变化均拒绝。

普通配置没有提供此本地 plan、探针白名单或保护拓扑。C 接线时需提供真实 provisioner，并显式连接 client 的 `ObserveV2 = runtime.ObserveV2` 与 server 的 `Observations = releases`；不能把管理请求改装为观察。当前端到端运行探针只确认其 canary 确实允许的配置。合法但不允许该 canary 的受限策略保持未验证，不把超时/REJECT 当作正向成功。V2 业务 UDP、公网出口和三层 DNS 同源仍待 T03。

## 显式迁移与 V2 节点移除

`DrainLegacyNode` 由可信调用者明确发起，沿 V2 transport 发送真正 format 1 的清理产物；只有 V1 空基线和所有可能已应用授权的真实清理都确认后，`SwitchNodeV2` 才创建空 V2 基线。幂等动作与 task 原子保存。原 V1 source 字节、Origin、Grant、墓碑和 clock floor 保留；普通 SubmitV2 仍不能仅凭能力切换活跃 V1 节点，升级后不再接受新 V1 执行。

V2 removal 复用 B02 真实移除意向和 B04 调度，不新增业务接口。移除标记一落库，B08 下载、迟到 reservation/dispatch 就检查 captured route 的全部节点，立即拒绝受影响线路；生成期间移除也会在输出前重查。worker 持久撤销受影响的真实意向/身份、封迟到操作、取消失效发布、移除当前 route head，保留历史确认记录。

入口通过原 B08 cleanup operation 和 generation 独立清理；收到真实确认前，entry/link 引用和端口均保留。入口清理后才退休失效发布的引用；最后引用退休后，对存活拥有节点提交独立的永久内部 cleanup。精确 listener 的子任务与移除任务关联，只有该节点真实 Applied+Cleanup confirmed 才释放其端口。共享且仍被其他线路使用的后缀不提前退休；其他入口和身份保持原样。

离线、未知 Origin、未确认回退或失败的清理保持 pending，不能靠超时、连接或其他节点 receipt 释放。被移除节点本身的物理清理也不冒充成功。含失效线路的旧订阅配置会被拒绝，须显式编辑订阅后生成；没有自动改写用户审阅的配置。内部从未 fetch 且无 Origin 的保留资源同样不在此处虚构 receipt 释放。

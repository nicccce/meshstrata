# I02 阶段二统一集成

2026-11-17（Asia/Shanghai）。会话 `01a1e530-9ab0-7d21-9101-4b50f8d45f1a`，`CODEX_THREAD_ID` 与 `CODEX_SESSION_ID` 一致。起点 `2d3c360b6c445805c0f4ec2374fc4603e730127d`，沿用 `codex/bootstrap-controller-agent`。B04 `01a1e45e-e12b-7171-8127-310995bd604e` 和 B05 `01a1e45f-10e5-7531-af72-0c819f8c484b` 的隔离报告继续记录原始交付。本轮独占集成写入，未远程部署。本地操作和后续真机步骤见 [T02 计划](T02计划.md)。

## 正式入口

- 安全 Controller 在进程状态锁内打开单个 SQLite Store，以同一 Cipher、Guard 和数据库组合 B02 enrollment、B04 Repository/Service 和 B02 Server。Results、Recovery、ArtifactResolver 和 Artifacts 均接 B04。HTTPS 和节点监听全部创建后启动调度及服务。退出先取消运行、关闭已劫持 WS，再回收 Store。保留原阶段一 Store 对无法入账的扩展结果拒绝回执的行为。
- 已注册任务 GET 列表/详情与 POST cancel/retry/rollback，管理写继续走管理员会话、Origin 和 CSRF。产物通过 mTLS 节点专用路由，核对目标、截止时间、epoch、DAG 屏障及密文绑定后传输实际 bytes。浏览器 API 只处理任务 DTO，前端继续 demo。
- trusted local 操作由 Controller 服务 UID 或持有其目录和密钥权限的本机操作者执行。停止 Controller 后运行 `meshstrata-controller submit-release -config controller.json < private-plan.json`，从 stdout 取得 task ID，然后启动 Controller。CLI 与运行中 Controller 共用排他锁，读取最多 4 MiB 的严格类型 JSON。B04 重新绑定 task ID、target 并审核 format 1，只接受发布、撤销、清理和回滚的受限编译输入。Bundle 无任意 YAML、宿主路径或脚本字段。代理凭据留在 stdin 源文件，生产计划写入时保持 0600；计划字段示例由联合驱动生成。
- Agent 默认 `control_only`。节点入网后可配置 `control.mode=runtime` 和 `runtime.mihomo_binary`，在同一状态目录执行 `prepare-runtime` 再启动。准备只在锁内初始化一次，密钥独立于 Controller 和节点管理身份。根目录与私有 runtime 子目录各有节点绑定标记，旧模式无法读取已准备的业务状态。checkpoint 使用 require-existing 模式。缺 key、错 key、损坏或校验失败时，启动失败并尝试通过原 launch record 和 pidfd 停止确切归属的历史实例。进程身份无法证明时保留拒绝启动与错误。
- 管理 socket 位于私有 `runtime/api/m.sock`，长度最多 100 bytes。生成配置和 Mihomo 工作目录共用 `runtime/config`，使 Mihomo 的 API 重载路径检查通过。材料仅以配置中登记的 `{id,purpose}` 读取 `runtime/config/materials/<id>.<purpose>`，TLS 路径受限且配对校验，REALITY 私钥文件内容只以受限内存值交给解析器。Agent 通过 B03 Adapter 和 B05 Store、Resolver、Process、Probes 执行，恢复完成后才连接 B02 Client。自主到期完成原子提交后在锁外通知重连。首次 Hello 后的 WS Ping/Pong 或有效业务帧确认短会话已建立，此后断线从初始退避恢复。
- 暂只接受 Linux amd64 的 Mihomo v1.19.33 锁定摘要，检查 `/proc`、pidfd 和私有路径。正常前台 Agent 退出保留独立的受管 Mihomo，`stop-runtime` 在 Agent 停止后显式停止该实例。systemd/OpenRC 正式独立服务生命周期、三角色和 frp 仍由后续安装阶段交付。单独停止 Agent 而保留内核期间没有本地到期执行者；Agent 恢复时会先按持久授权账本过滤。

## 事务与协议

- 正式安装 006 B04 和 007 B05（Agent 独立账本，无 Controller 表）。001–005 字节保持基线；`golang.org/x/sys v0.49.0` 从已有间接锁改为直接依赖，`go.sum` 使用既有锁。本轮只通过 sqlc 更新生成物。升级验证以 001–005 数据库中已有证书字节、密文、引用、待清理端口及实例 ID 为种子，核对完成迁移后保持，强制 007 失败验证 006、007 同时回滚。
- 006 校验 task/node/target 修订与摘要，强化 grant 不可变绑定、首次来源和跨节点外键。持久完整规范化 Result JSON、SHA-256 和逐 identity Restriction，再发精确 receipt。历史结果可重放和校验冲突，过期或终态发布不会被迟到结果改写。清理未覆盖全部目标时命令保持 pending，逐身份回执可释放已确认子集。未知会话使清理证据未确认，或在能够确认进程归属时触发保护性停止。
- 正式分配路径在同一 `storage.Database.Write` 内调用 `ports.CheckAvailable`，共同扫描 002 与 006 两套未释放行，按数值 IP、TCP/UDP、wildcard 与 IPv6 双栈规则判冲突。B04 自身同一 Listener/identity 的精确复用可继续。未来 002 的新分配传空 owner，复用既有行时应沿所属账本引用该行，勿镜像另占同一绑定。006 为 002 新写入增加规范地址的数据库交叉保护；数值地址比较以事务内的共同入口为准。006 仅在同 identity/listener 的清理确认且两套账本均零活动引用时释放，002 仍由其 Listener 的确认和引用规则控制释放。
- Hello 的 `applied_revision` 与 `applied_digest` 指最近经确认的 Controller artifact。首次、只落 Candidate/Applied、尚未恢复或失去校验时可为 0/空，旧的已确认历史保留在 Controller；此观察不创建 Verified 或 cleanup 证据。业务 Agent 附带可选 `runtime:true`，旧 `control_only` 可按原 pristine Hello 安全上线。调度只向已完成 Hello 的业务 peer 送命令。验证后的 Result 提交独立 `effective_digest`，离线过滤后的渲染摘要使用 Restriction；旧发布的 artifact 内容及摘要保持不变。
- 首次 Open 和结果确认之间无法推断 Agent 已经持久 grant。原任务尚有效可重投同一 task/node/target/digest。原任务已终态且该 grant 的来源目标未确认时，重发该身份的换 task 重试明确拒绝 `GRANT_ORIGIN_UNCERTAIN`。可发显式撤销/清理计划；已知 grant 按原来源确认并回执。仍未知的旧占用保留 pending。需要恢复业务时可在另一仍授权节点以新 identity、凭据和可用端口正常发布，保留原任务、墓碑与占用。不能通过换来源、重置账本或重入网旧身份解除该状态。
- 真实应用与回退均重新校验内容及监听。REJECT 规则保持实际阻断，format 1 现有正向业务探针下结果为未验证或失败，回退仍按真实证据单独确认。format 1 DAG 只验证目标激活次序，模板仅配置单节点 DIRECT/REJECT，线路级多跳编译留后续模块。
- B02 移除先断开旧 WS/证书。发布账本只为关系明确、仍授权且满足约束的 peer 生成独立清理任务；移除节点自身、离线 peer 或共用 Listener 保留待确认。现有发布关系依赖 002 路线关联，格式 1 双节点 DAG 不凭自身推出对端该清理的 Listener。

## 验证与边界

验证日志保存在本机忽略目录。所有网络场景均为本机回环和本轮私有进程；T01-N02 是旧阶段的独立公网门槛。

- 早期 `.local/i02-compile-01.log` 记录默认沙箱 Unix socket 权限拒绝。首次 `.local/i02-joint-01.log` 至 `03.log` 保留离线到期时保留连接中断，原因为正式装配将候选目录放在 Mihomo 工作目录之外，冷启动可用但在线重载失败。纠正后保持原断言，通过同 PID、旧连接消失和另一个身份的同一存量连接转发取证。
- `.local/i02-joint-04.log` 和 `.local/i02-make-check.log` 记录两个 fixture 运行环境问题。新的 B05 测试临时目录显式设为 0700 后可用默认文件掩码；全局扫测使用 022，避免 077 将 B01 的预期宽权限负向 fixture 变为 0600。
- `.local/i02-joint-07.log` 记录频繁短会话后的健康节点退避超出观察窗口。Agent 现在在经认证的 WS 上用首次 Hello 后的 Pong 或有效业务帧确认已建立会话，并重置后续退避。生效前后均保留实际网络重连和成功发布断言。
- `.local/i02-materials-01.log` 和 `02.log` 保留 VLESS 对 Ed25519 测试目标未验证的首次结果，运行时输出非敏感协议、监听及转发检查状态。使用与 B05 基线一致的 P-256 TLS 目标，正式 Agent 的本地材料路径通过 Trojan、Hysteria 2、VLESS 的 TCP、业务 UDP 及错凭据检查；Ed25519 目标未计通过。
- Linux SIGSTOP/SIGKILL、只读测试副本和磁盘断点场景用于检查软件恢复。同权限主体整体回滚受信目录及高水位时，本地账本无法独立识别。电源中断耐久性以及不同硬件/文件系统需独立验证。checkpoint 永久账本上限 256 MiB，产物及渲染 GC 预留；错误按保护路径处理。
